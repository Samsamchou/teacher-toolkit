# 3D 人物建模檢查清單（所有 Tripo／Mixamo 綁骨人物都要跑）

> 來源：2026-11-09～10 二水小行星 Free Time 版（Ken、圳寶、水鈴）。之後任何專案（小行星、Jump Island、科幻雙老師、桌上微縮、Stand Out Fit In 3D…）**新做或第一次使用**一個綁骨人物，都先照這份檢查，再做動作。
> 工具在 `tools/2026 REA Games/3D planet/godot-ershui-freetime/`（Godot 4.7.2）；Blender 版的專案照同樣原則在 Colab 上做。

## 1. 拿到模型先做的 4 個檢查（10 分鐘）

| # | 檢查 | 怎麼查 | 踩過的坑 |
|---|---|---|---|
| 1 | **雙手是不是都張開、手指會彎** | `scripts/mascot_hands_check.gd`：雙手特寫＋手指彎 60°，並印出每根手指骨頭綁到幾個頂點（某邊手指骨頭幾乎 0 → 那隻手是一顆拳頭） | Ken 右手是握著小道具的拳頭（戴黑手套）、圳寶右手是一顆圓球；水鈴手很小，一彎就出尖刺 |
| 2 | **靜止姿勢是不是 T-pose** | 不播動畫直接截圖（`ONLY=rest`） | Ken 的模型是「右手舉高」的姿勢 → 直接套 Mixamo 動作，每個動作右手都卡在臉旁 |
| 3 | **骨架名稱** | 印 `Skeleton3D` 骨頭名；Tripo 綁骨＝65 根 `mixamorig_*` | 名稱一樣才能直接套 Mixamo；不一樣要做 BoneMap |
| 4 | **描邊粗細** | 用遊戲實際的 `fit_model(…, true, 0.3)` 截圖，不要用 1.0 | 粗描邊把 Ken 吃成黑影，老師認不出來；手指只有 1.2 cm 粗，手部描邊要再細（`Pose.thin_hand_outline(ken, 0.25)`） |

## 2. 修法

### 2a. 握拳／壞掉的手 → 把好的那隻手鏡射過去（0 點，不用 Blender）
- 工具：`tools/make_openhand.py <角色>`（Ken 的第一版是 `make_ken_openhand.py`），輸出 `<角色>_openhand.glb`，**原檔不動**。
- 做法：好手用 flood-fill 選出 → 刪掉壞手到袖口 → 在「T-pose 座標」鏡射（`S = HR⁻¹·diag(-1,1,1)·HL`，HL／HR 用 `retarget.gd _build_corr` 同一套最短弧規則算）→ 換掉壞手手指骨頭的靜止姿勢與 inverse bind → 手腕縫一圈三角形 → 內建動畫的手指軌也鏡射。
- **坑**：不能在模型的靜止姿勢裡鏡射（手臂不對稱）；也不能直接本地 X 鏡射——Ken 右手骨頭的座標軸比左手多轉了約 81°，直接鏡射手掌會朝反方向。
- **驗收**：鏡射後 20 個手指關節誤差 0 mm；手放下時兩手拇指都朝前；手指彎 45°／80° 不破；Mixamo cheering／dribble／typing 手腕不撕裂。
- **圳寶（2026-11-10）多了兩個坑**：①拳頭那隻手的 `RightHand` 骨頭被 Tripo 綁歪約 70°（拳頭沒有手指可對齊）→ 工具會把那根骨頭的靜止角度改成「左手對前臂角度」的鏡射，並重算 inverse bind；內建 walk 的右手腕軌也用左手腕軌鏡射。②切口要沿「前臂方向」切、切在顏色單純的地方（圳寶切在白色前臂，不要切在橘色環上，會有鋸齒色塊）；手指骨頭沒頂點時，從前臂最遠的頂點開始找手。每個角色的差異寫在 `make_openhand.py` 的 `CFG` 表：`python -I tools/make_openhand.py ken|zunbo`。
- 已知小瑕疵：袖口比另一邊短時，手腕會露出一圈縫合的膚色帶（遊戲距離看不出來）；換手後手套會消失（Ken 右手變成沒戴手套）。
- 真的鏡射不了（例如兩手都壞）→ 再報價用 Tripo 重綁或重做。

### 2b. 靜止姿勢不是 T-pose → 重定向先轉 T-pose
- `scripts/retarget.gd`：`_build_corr()` 先把目標每根骨頭轉到和 Mixamo 來源 T-pose 同方向，動作再疊在上面（世界座標的旋轉差）。只有 Hips 搬位置，依臀高比例縮放。
- 檢查圖：`scripts/anim_check.gd`（每個動作抽 25%／50%／75% 三格）。

### 2c. 手和物品重疊 → 用網格實際量，不要目測
- `procedural_pose.gd`：`hand_points`／`hand_low`／`hand_gap`／`hand_line_clearance`（用擺好姿勢後的實際頂點）；`rest_hand_on`、`hold_pencil_open`、`hand_on_tube`、`lift_feet`。
- 驗收數字：手最低點在書頁／鍵盤／大腿上方 2–5 mm；手到鉛筆、直笛軸線的距離 ≥ 半徑；所有身體頂點在書、桌、鍵盤裡面的數量＝0。
- 老師的規則：道具要碰到目標、手不擋臉、坐著屁股在椅面、腳垂到地、人面向他在做的事（也見 [[程式動畫動作要合邏輯]]）。

## 3. Mixamo 動作下載的坑
- 老師在 Chrome 用 Adobe 帳號登入；用頁面 API 匯出（`/api/v1/animations/export`，Without Skin、fbx7_2019、30 fps），太快會 HTTP 429，要分批。
- Chrome 會擋同一網站連續自動下載；被擋的檔變成 `<uuid>.tmp`（內容完整）→ 用 Godot `FBXDocument` 讀臀部高度分辨坐姿／站姿再改名。
- 授權：可用在作品裡，但 **FBX 原檔不入庫**（`.gitignore` 有 `*.fbx`）。

## 4. AI 影片裡的同一個人物（KIE Seedance 首幀模式）
- 首幀用 Codex 畫（`codex exec -i 參考圖.png -`，參考圖用 Godot 截的人物多角度圖）。
- **比手畫腳（無道具）影片**：提示詞裡**不要寫任何物品名稱**（連 imaginary bat、invisible ball 都不要寫），只描述身體怎麼動，並寫「舞台地板全程空的、手裡全程沒東西」——第一批 10 段裡 9 段 AI 自己變出了球棒、腳踏車、沙發、營火、直笛，浪費約 443 點。
- 新提示詞先用 480p（約 23 點／6 秒）試 1–2 段，抽格確認沒有冒出道具，再批次 720p（約 49 點／6 秒）。

## 5. 動作合邏輯檢查（所有 3D 人物專案＋所有程式動畫都要跑）

> 來源：2026-11-10 Free Time 小行星 iPad 預覽，老師抓到 5 個不合邏輯的畫面（描邊太粗、電視被按鈕擋住、腳踏車輪子陷地 1/3＋腳沒踩踏板、運球手沒碰到球、棒球沒碰到棒子就飛＋跑壘還拿著棒子）。11 段 2D 程式動畫線索也有同樣的毛病。細節：`tools/2026 REA Games/3D planet/資料/freetime/motion-findings.md`。
> 老師的規則：**每個動作都要符合真實世界的物理和邏輯。**

### 5a. 道具由「接觸事件」驅動，不用計時器
- 先問每個會動的東西：「**誰讓它動？**」（手、腳、球棒、地板、遙控器、樂器、喇叭）。沒有原因就不能動、不能出現、不能消失。
- 球只有碰到東西（手、地板、球棒、籃框）才改變方向；兩次碰撞之間是拋物線（重力），不是 `abs(sin(時間))`。
- 運球：手往下推時球貼手心 → 放手 → 落地 → 反彈 → 剛好在手最高點回到手心。
- 棒球：來球 → 揮棒那一格棒面碰到球 → 球才飛出 → 跟進揮完 → 丟棒（棒子掉在地上）→ 空手跑壘。
- 腳踏車：腳踩踏板 → 曲柄轉 → 鏈條 → 輪子轉；輪子轉角 × 半徑＝前進距離（地面退的速度＝輪胎外緣速度）。
- 音符從樂器／喇叭／耳機出來；火只在原地閃；腳印在鞋子離地後才看得到；按了遙控器、訊號到了電視才換台；分數在得分事件（落地、碰到）時才加。
- 實作：道具位置寫成「動作時間的函數」，每一格先更新動作（Godot `AnimationPlayer` 改手動 `advance`）再算道具，道具才不會慢一格。

### 5b. 接觸點用量的（網格頂點／程式座標），不要目測
| 接觸 | 標準 | 量什麼 |
|---|---|---|
| 手到球 | ≤ 2 cm | 擺好姿勢後手掌網格到球面 |
| 輪子到地面 | ±1 cm | 輪胎**外緣**最低點到「這裡的路面高度」（不是 y＝0；柏油、人行道、門口高度都不同） |
| 腳到踏板 | ≤ 2 cm | 鞋底網格到踏板上緣 |
| 球在棒面 | ≤ 3 cm | 接觸那一格球面到棒面 |
| 2D 程式動畫 | 0–1 px | 寫成檢查函式（例 `clue_anim.gd gaps()`），檢查場景每次印出來 |
- 穿入的頂點數要列出來（目標＝0）；不互穿也要查「接觸之外」的格子（例：揮完的棒子不能追上球）。

### 5c. 動作結束不能還拿著道具
- 打完棒球丟棒、下車後腳踏車停在旁邊（不是憑空消失）、看完電視遙控器放下。
- 道具出現／消失一定有原因（拿起、放下、從畫面外進來、離開畫面），或整個畫面淡入淡出。

### 5d. 關鍵物件不能被 HUD 或下方面板蓋住
- 演出鏡頭自動檢查：把重要物件（電視、課本、球、腳踏車）投影到螢幕，不能落在右側按鈕欄或下方題目面板（Free Time 的 `_hud_safe()`，整回合每題都檢查）。
- iPad 是 4:3，左右比 16:9 窄 → 重要物件放畫面左側或中間。

### 5e. 近景描邊要變細
- 遠景（戶外）描邊 0.3；室內近景約一半 0.15，手部再 ×0.25。描邊太粗會把手、臉吃掉。

### 5f. 移動不能滑腳
- 移動速度要和動作的原地踩地速度一致（播放倍率＝速度 ÷ 原地速度）；路太長用淡出跳段，不要把人加速到不合理。
- 擺動的腳不能刷過地面；站、跪、坐的最低點要量（不陷地、不浮空）。

### 5g. 發布前的 4 格檢查圖
- 每個活動（× 每個角色）拍 4 個關鍵畫面：**準備／接觸／動作中／結束**，每格英文標籤＋一行說明接觸的是什麼、量到幾 cm／px。
- 老師看過檢查圖通過才部署。範例：`3D planet/資料/freetime/motion-check-clues-v1.png`（11 段程式動畫線索）、`motion_check.gd` 的 Ken／水鈴／圳寶戶外活動檢查圖。

### 5h. 換角色（吉祥物、小孩）時再量一次
- 道具照角色尺寸縮（輪子、球、球棒、握把粗＝手寬）；短腿角色的走跑速度、抬腳門檻要另外算。
- 「量 0」不一定是沒碰到：封閉的大頭、裙子會讓頂點距離量錯 → 用深度圖量「在裡面」、坐姿排除裙子頂點。

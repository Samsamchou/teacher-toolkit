# AI 評分用量與費用門檻 / AI scoring usage and cost limits

- 正式站可評分題目：84 題（HWG5 44 題、HWG7 40 題）。
- 班級估算：26 人。
- 每題每日成功評分上限：3 次。
- 理論每日上限：`84 × 26 × 3 = 6,552` 次。
- 每日規劃門檻：7,900 次，約保留 20% 緩衝。Firebase AI Logic 目前沒有相對應的「每日要求數」硬配額，因此此值是容量與費用規劃值，不宣稱為雲端硬上限。
- 已設定 Firebase AI Logic `Generate content requests` 預設配額為每位使用者、每區域每分鐘 60 次，可容納一班同時送出評分並降低濫用風險。
- 已部署版本會以 Firebase 匿名登入取得每台裝置的使用者 UID，並用本機與 Firestore 紀錄交叉檢查每題每日 3 次；這可降低一般誤用，但不宣稱為完全不可繞過的費用硬上限。
- Firebase AI Logic 的 App Check 基準防護已設定為強制執行；重放攻擊防護維持監控模式，避免額外延遲與費用。
- 已於 2026-08-27 建立 Cloud Billing 月預算「HWG5 每月 NT$300 預算警示」，警示門檻為實際支出的 50%、80%、100%，由 Google Cloud 寄給帳單管理員和使用者。
- 控制台將此預算顯示為套用於「Firebase 付款」帳單帳戶；設定當時該帳單帳戶只連結 `hwg5-su-to-u04-story` 一個專案，因此目前實際涵蓋範圍等同 HWG5 專案。若日後連結其他專案，必須重新加入明確的專案篩選或建立獨立預算。
- Cloud Billing 預算警示只會通知，不會自動停止服務或限制支出。

## 2. 作者的五步驟流程

1. 生成場景參考圖
2. 把場景拆成一個個獨立元素，每個元素產出三視圖
3. 依三視圖生成各元素的 3D 模型
4. 在 Godot 裡把模型拼成場景（下期）
5. 調整燈光與渲染參數（下期）

### 步驟 1：生成參考圖（00:59–02:27）
三個技巧：
1. **先給風格參考**：作者給兩個參考，一個取「構圖」（寶可夢的視角），一個取「美術風格」（原神）。
2. **讓 AI 先調研**：先請 AI 搞清楚那兩個參考到底是什麼構圖、什麼風格。
3. **先寫提示詞、不要直接生圖**：讓 AI 先構思出一段很長的詳細提示詞，再複製到新對話去生圖。
- 因為生圖模型對「鏡頭角度」控制不精準，所以新對話裡**把調研時找到的參考圖一起貼上**，當作視角範例。
- 第一張視角太近 → 補一句「攝影機拉遠，場景擴大四倍」，建築就變多、畫面更開闊。
- 畫面規格：約 45° 俯視（camera pitch 約 45°、yaw 0°）、正前方往街道延伸。

### 步驟 2：拆解元素成三視圖（02:27–07:03）
分兩段，**不要直接把參考圖丟給 Codex**（提取會不準）：
- **2-1 先讓 ChatGPT 規劃**：給它參考圖＋一段提示詞，請它「數」圖中有幾棟建築、幾根電線桿、幾座欄桿，然後替每個元素各寫一段生圖提示詞，整理成一份 Markdown 檔。本例輸出 **82 個資產單元**（建築 10、遠景 4、地面 1、基礎設施 12、交通工具 4、擺件 24…），共約 313 次生圖。
- 該提示詞的重點規則：
  - 地面與遠景**不做三視圖**，各提取成一張平面圖。
  - 三視圖一定要**正交視角**（沒有透視、不能看到側牆），每個元素各產出：原圖、正視、右側視、頂視。
  - **不能有懸空部分**，被遮住的地方要補完整。
  - 背景統一成單一純色（作者提到現在也能直接要求透明背景）。
  - 因為平行（並行）生成，每段提示詞都要獨立完整，不能寫「同上」。
- **2-2 再讓 Codex 批次生成**：新建 Codex 專案，放入「提示詞合集.md」和原始渲染圖。指示 Codex 一次叫 10 個子代理（sub-agent）並行呼叫生圖工具；先照原圖生成原圖視角，再生成正、側、頂三視圖。
- 模型選擇：**用最低檔、思考模式選低或中**即可，因為只是照提示詞無腦生成。整個步驟約用掉不到 20% 的額度。
- 檢查：看三視圖是否真的正交，角度差太多就請 Codex 重做。

### 步驟 3：生成模型（07:03–13:45）
作者示範兩種方法。

**方法 A：Codex 操作 Blender（品質高、很耗額度）**
- 安裝 Blender（免費），再用 Codex 設定 **Blender 官方 MCP**（直接把官方說明網址貼給 Codex，說「我已安裝 Blender，請幫我設定這個 MCP」即可）。
- 建模提示詞要改／交代的事：
  1. **面數上限**依元素複雜度調整：普通建築約 4000 面；較複雜（如便利商店、含販賣機與內部櫃檯）6000–8000 面；小物件（號誌燈）約 1000 面以下；結構很簡單的（路障）約 500 面以下。居酒屋因零件多給到 8000。
  2. **邊緣要有適度倒角**（圓角）：邊緣會多一道高光，看起來更立體。
  3. **自行生成貼圖**：牆面、葉片、門框、招牌都要有獨立的材質貼圖，還要**同時生成法線貼圖**（紋理與材質貼圖吻合，用來做凹凸質感）。
  4. **完成後自我檢查**：360° 轉一圈，看有沒有穿幫、穿模、閃爍（重疊面）。
- 交付物：**Blender 工程檔＋GLB 檔**。GLB 是之後匯入遊戲引擎的檔案；它本身沒有燈光、陰影、環境光遮蔽、全域光照，所以直接看會很陽春。在 Blender 按 F12 渲染才會看到有光影的效果。
- 缺點：非常耗額度，作者說 5 小時的 Plus 額度大概只能做兩個模型。

**方法 B：騰訊混元 3D（免費、較粗糙）**
- 選「圖生 3D → 多張圖」，上傳正視、側視等，選 3.1 版、面數最高 **50K**（無法更低）。每天約 20 個免費額度。
- 問題：面數太多（整個場景會很卡）、文字無法還原、佈線不規整、稜角多或細節多的模型會失敗；只適合方正簡單的房子。
- 作者建議：不要大量使用。

## 3. 畫面裡看到的、旁白沒有細講的細節
- 元素分類後，檔案命名有規律：`B01_original / B01_front / B01_side / B01_top`（建築編號 + 視圖）。
- 實驗頁面：作者做了小網頁對照「有倒角／沒倒角」「有法線貼圖／沒有」的差異，用來教學。
- 咖啡店模型資料夾裡有 `basecolor`、`normal` 兩套貼圖（磚、灰泥、木、葉叢、招牌等各自一組），表示貼圖是**按材質分檔**，不是整棟一張大圖。
- Blender 專案資料夾裡有一組 JSON／log（幾何稽核、交叉檢查、面片檢查、最終驗證、重新匯入驗證），顯示作者讓 AI **自動稽核模型品質**。
- 最後幾張畫面是 Godot 4.6 場景：節點樹分成 `Ground（地面）／Poles（電線桿）／FlowerBoxes／Boards（看板）／Bikes／Fences` 等群組，有 `main_day` 與 `main_sunset` 兩個場景（白天、黃昏）。路面、斑馬線、導盲磚、櫻花樹、車站與店家排成街景。

## 4. 作者做法的限制（要避開的坑）
1. 影片只教到「模型」，**如何在 Godot 拼場景、打光、做 HD-2D 效果沒有教**（下期內容），這部分要自己設計。
2. 方法 A 很耗額度；方法 B 面數過高、文字糊，不適合大量用在網頁遊戲。
3. 三視圖常常不是真正正交，要抽查。
4. 作者的素材是日本街景，不是真實地點；我們要做**真實的二水地點**，多一道「參考照片→建築特徵」的步驟。

### 5-1. Tripo 使用前待確認（依規格卡建議④）
這些是我**沒有在影片裡看到、也尚未查證**的事項，動工前要先確認：
- 你的 Tripo 方案與可用點數；每個模型約耗幾點；是否提供面數上限設定。
- 免費／付費方案的**商用與課堂公開網站授權**。
- 是否支援多視圖輸入、是否輸出 GLB 與貼圖。

### 5-2. 二水專案的建議製作順序
1. **小樣本**（規格卡建議①）：1 段街道＋第一味（飲料店）＋1 隻小怪＋1 隻魔王＋各題型 1 題，用來驗證 Tripo→Godot 流程、iPad 效能與題目互動。
2. 確認小樣本品質與面數後，才依資產清單批次生成剩下 12 個地點。
3. 題庫沿用 `escape room HWG5-U01-U02` 的 32 題，另做 16 題聽力選擇題（`content/question-bank.v0.1.json` 格式延伸）；遊戲與題庫分離。
4. 作答紀錄只用座號與班級代號，沿用 `hwg5-clock-tower` 的存檔／教師後台架構；未經確認不部署。

## 6. 提示詞可借用的框架（用自己的話改寫）
- **規劃提示詞**：「我要請 Codex 批次提取場景元素；請數出建築／植物／擺件各幾個，替每個元素各寫一段獨立的生圖提示詞並整理成 Markdown。注意：地面與遠景做成單張平面圖；三視圖必須正交、不含透視；被遮住的部分要補完整；背景為單一顏色或透明；每段提示詞要獨立完整。」
- **建模提示詞**：「還原參考圖的建築形態與美術風格；佈線要適合遊戲、有規則；邊緣適度倒角；總面數不超過 N；自行生成材質貼圖與法線貼圖；360° 無死角、無重疊面、不穿模、不懸空。」
- 其中「面數 N」依元素複雜度調整（見上方面數預算）。

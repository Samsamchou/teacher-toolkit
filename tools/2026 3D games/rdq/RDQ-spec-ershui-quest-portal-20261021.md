# RDQ 需求規格：二水 3D 英語闖關上架

## 一句話任務
把二水 3D 英語闖關（51 題）放進 hwg5-clock-tower.web.app 首頁成為新任務卡，學生輸入學號開始，紀錄進教師後台並換算 100 分，換 iPad 也能接續。

## 已確認
- 首頁新增一張任務卡；流程：Start → 輸入學號（5–8 位數字）→ 遊戲 → 結果頁。
- 計分（1A）：每題 100/51 分 × 品質比例；一次答對 4/4、錯一次 3/4、錯兩次 2/4、三次以上 1/4；總分四捨五入到整數。
- 接續（2B）：換一台 iPad 輸入同一學號也能接著玩 → **需要改 Firestore 規則**。
- 後台（3A）：沿用現有後台（日期 → 全班列表 → 學生明細、需重試題目、CSV），加一欄「總分」。
- 上線（4A）：先部署 Firebase 預覽網址（7 天失效）給教師 iPad 實測，教師同意後再部署正式站。
- 任務卡名稱：**二水 3D 英語闖關 HWG5 R1**，任務代號 `ershui-3d-quest`。
- 作答紀錄沿用 `questAttempts` 格式（51 題 ≤ 規則上限 60 題），保存一年三個月。

## 待確認假設
- （已確認）跨裝置接續：新增集合 `questProgress`，文件 ID＝任務代號＋學號，只存「已通關地點、各題作答狀態」，任何登入裝置可用學號讀寫（不能列出全部）。**風險：知道別人學號的同學可以讀到或覆蓋別人的進度**（不含姓名，只有學號與作答）。若要防止，可加一組 4 位數「通關密碼」，學生第一次自訂、之後換裝置要輸入（多一步操作）。教師確認：**不加密碼**，接受此風險。
- 同一學號再玩一次 → 預設從上次進度接續；全部通關後按「再玩一次」才開新紀錄。
- 結果頁 → 預設沿用現有結果頁風格，顯示總分、星星、學號。
- 規則部署前先用模擬器測試，並確認 english-portal 與既有兩個任務的行為不變。

## 已採納建議
- ① 遊戲檔壓到約 50 MB 以下（貼圖改有損壓縮），再做畫質檢查。
- ② 學號、Start、存檔、上傳由網頁外框處理，沿用 `quest-cloud.mjs`；Godot 只回報每題結果。
- ③ 學生結果頁顯示總分和星星。
- ④ CSV 匯出加入總分與各題得分。

## 本次不納入
- 學生名冊、姓名（維持只用學號）。
- 修改既有 HWG5、HWG7 任務內容。

## 一段式需求規格
在 **hwg5-clock-tower.web.app**（Firebase 專案 **g6-english-online-learning**，Hosting site **hwg5-clock-tower**）首頁新增任務卡「**二水 3D 英語闖關 HWG5 R1**」（代號 **ershui-3d-quest**），指向 Godot 4.7.2 Web 版二水 3D 英語闖關（**51 題**：HWG5 U01+U02 拼字／拖放 32 題＋HWG5 R1 聽力 19 題）。網頁外框負責 Start、學號（**5–8 位數字**）、存檔與上傳，沿用 `shared/quest-cloud.mjs` 寫入 `questAttempts`；Godot 透過 JavaScriptBridge 回報每題 attempts／品質／是否答對與通關地點。總分＝Σ(100/51 × 品質/4)，四捨五入。新增 `questProgress`（文件 ID＝任務代號＋學號，只存已通關地點與各題作答狀態，登入裝置可用學號讀寫、不能列出全部，不加密碼）讓同一學號換 iPad 可接續（需改 Firestore 規則並先用模擬器驗證，不影響 english-portal 與既有任務）。教師後台加「總分」欄，CSV 加總分與各題得分；學生結果頁顯示總分與星星。遊戲檔壓到約 **50 MB** 以下。先部署 Firebase **預覽頻道**給教師 iPad 實測，經教師同意才部署正式站；不寫入金鑰，不新增付費資源。

## 驗收條件

- [ ] 同一學號在第二台裝置可從原進度接續
- [ ] 規則模擬器測試通過，english-portal 與 HWG5／HWG7 任務行為不變；遊戲檔 ≤ 約 50 MB

## 二、各階段詳細流程

### 0. 需求釐清（RDQ）
- 大改動一律先產規格卡（`status: draft`），教師確認後改 `confirmed` 才做。
- 教師貼回建議清單＝全部採納；貼回假設清單＝同意這些假設。
- 已確認事項不重問；新對話先讀規格卡與交接筆記。

### 1. 影片分析
1. ffmpeg 抽音訊（16 kHz 單聲道）＋每 10 秒抽一張畫面，拼成 4×3 縮圖看。
2. faster-whisper small 語音辨識 → 逐字稿，人工校正同音字（「高德」＝Godot、「三式圖」＝三視圖）。
3. 報告只記方法、用自己的話改寫；影片原檔與截圖不放進專案。

### 2. 素材查證
- Tripo 官方價格頁（第三方資料互相矛盾，以官方為準）：Free 方案模型公開、非商用；Pro 可商用、私有。
- 13 個地點在 Google 地圖逐一看照片，**只用文字記特徵，不下載照片**；名稱以地圖為準（「二八水水公園」「水心之初大草原」「7-ELEVEN 二八水門市」）。
- 二水車站 2025-12 整修完成，外觀要用最新照片（台灣設計研究院專案頁）。

### 3. 3D 建模（Tripo）
1. 參考圖：Tripo Image（免費額度用完後改 **ChatGPT API gpt-image-2**，medium、1024×1024，每張附 .json 與 SHA-256）。
2. 提示詞固定句：`stylized low-poly toy-like game asset, isolated on plain light grey background, three-quarter view from front-left, no people, no text`。
3. Generate HD Model：**Polycount 改 5000**（預設 200 萬）、**Privacy 改 Private**、4K PBR；每個 55 點。
4. 匯出 GLB（2k 貼圖），匯出不扣點。
5. 用 GLB 內嵌貼圖名稱核對檔名，再複製到 `assets/models/`。

### 4. Godot 場景
- 路網用簡圖像素座標寫 `NODES`／`EDGES`，`w()` 轉世界座標；Dijkstra 找路。
- 模型載入後依外框置中、貼地、等比縮放到指定大小（Tripo 模型都被正規化成約 1 單位）。
- 鏡頭三種：走路越肩、打怪第一人稱、地圖俯視。
- 自動測試：`Godot_console.exe --path . -- --test`（截圖）、`--shots`（13 地點攻擊畫面）、`--perf`（攻擊幀時間）、`--mobile`（模擬 iPad 特效量）。

### 5. 答題系統
- `tools/build_quiz_data.py`：從 HWG5 網站 `data.js` 轉出 32 題＋19 題聽力 → `data/questions.json`、`data/quiz_plan.json`。
- 規則沿用 HWG5：品質 = max(1, 5 − 嘗試次數)；答錯出提示；答對聽 Tick 語音才可下一題（聽力題不用）。
- 聽力 11–17 題音檔：`tools/generate_listening_tts.mjs`（gpt-4o-mini-tts／marin／0.8 倍速），whisper 轉文字核對。
- 聽力 7–12 題插圖：ChatGPT API 13 張，逐張檢查字樣（Mon./Tue./90/100…）。

### 6. 打怪
- 一般地點隨機 2 隻（6 種原創怪物），魔王區各 1 隻；愛心＝該地點題數。
- 最終版：答完全部題目 → 「Combo」→ 學生按 **Attack! 攻擊**（20 秒沒按自動發動、剩 2 擊以上可「全部發動」）。
- 8 種非暴力攻擊（泡泡、光束、棒球、籃球、星星、水柱、火焰、強風），一律最華麗；4 星那一擊 Critical；魔王加震動、閃光（≤0.15 秒）、雙倍粒子、最後一擊慢動作煙火。

### 7. 聲音
- Suno（教師帳號、免費方案）三首純音樂 → ffmpeg 轉 96 kbps 約 1.8 MB；原檔留 `suno-bgm-original/`。授權：非商用、標示 Music: Suno。
- Kenney CC0 音效 21 個共 157 KB，授權檔放在 `assets/audio/sfx/`。
- 答題時背景音樂降 20 dB（約 10%），攻擊時恢復；右上角音量 4 段（預設小聲）。

### 8. 主角動畫
- Ken 原模型 195 萬面 → Tripo Retopology 1 萬面（35 點）。
- Tripo Rig（Humanoid／Mixamo，20 點）→ Animation 預設「walk」「idle」（不扣點）→ 匯出勾 **Animation stay in Place**、選全部動畫。
- Godot 用 AnimationPlayer：走路播 walk、停下播 idle，0.25 秒混合。

### 9. 網頁版匯出
1. 下載 Godot 匯出範本（1.28 GB，只解出 web 部分到 `%APPDATA%/Godot/export_templates/4.7.2.stable/`）。
2. `export_presets.cfg`：Web、不用多執行緒（Safari 不需特殊標頭）、只開 mobile 貼圖壓縮。
3. 中文字型：Noto Sans TC（OFL）用 `tools/build_cjk_font.py` 裁成只含遊戲用字（約 180 KB×2）；新增中文字要重跑。
4. 模型貼圖匯入上限 1024、聽力插圖 512。
5. 匯出到共用資料夾 `site/public/quest3d/`（遊戲本身不含題目，約 45 MB）。題庫另外用 `tools/build_mission.py` 產生（見第 11 點）。

### 10. 上架與教師後台
- 網頁外框負責 Start、學號（5–8 位數字）、存檔、上傳；Godot 透過 `scripts/host.gd`（JavaScriptBridge → `window.parent.ershuiHost`）回報每題結果。
- 紀錄寫 `questAttempts`（沿用既有格式與後台）；新增 `questProgress` 讓同學號換 iPad 接續（不加密碼，教師接受風險）。
- 計分：Σ(100/51 × 品質/4)，四捨五入。後台加總分、CSV 加各題得分。
- 先 `firebase hosting:channel:deploy ershui-preview --expires 7d` 給教師實測，教師說「部署正式站」才 `firebase deploy --only hosting:hwg5-clock-tower --project g6-english-online-learning --account u9431818@gmail.com`；部署前 `npm test`、部署後用 curl 讀回首頁卡片與遊戲檔大小。

### 11. 共用遊戲＋任務題庫（2026-10-21 改架構）
- 遊戲（`quest3d/`）只有一份，所有 3D 任務共用；題目、插圖、語音、聽力音檔、中文字型放在各任務的 `<任務>/bank/`。
- 開場由網頁外框給 `bankBase`，遊戲下載 `bank.json` 與素材（畫面顯示「Loading questions… %」）；電腦測試用 `--bank=<資料夾>`。
- 新任務：`python -I -X utf8 tools/build_mission.py --mission <代號> --unit "<中文名>" --title "<英文名>" --questions <questions.json> --plan <quiz_plan.json>` → 放 `cover.webp` → 把程式印出的一行貼進 `shared/missions.mjs`、卡片貼進首頁。格式說明：`godot-ershui-quest/tools/BANK-FORMAT.md`。
- 任務頁 `index.html` 只有三行程式：載入自己的 `data.js`，交給 `shared/quest3d-app.mjs`（學號、存檔、上傳、結果頁）。
- 每個任務的進度各自獨立（本機鍵 `quest3d:v1:<任務>:<學號>`；二水 HWG5 R1 沿用舊鍵，學生進度不會遺失）。
- 舊版單機匯出（`ershui-3d-quest/game/`、`app.js`、`style.css`）移到 `site/_retired/`，不部署、不進 git。

## 三、踩過的坑（症狀 → 原因 → 解法）

### 環境與工具
| 症狀 | 原因 | 解法 |
|---|---|---|
| faster-whisper 讀 wav 報 `metadata_errors` 錯 | PyAV 版本不相容 | 改用 soundfile 讀成陣列再丟給模型 |
| PowerShell 5.1 執行含中文註解的 .ps1 出現亂碼錯誤 | 檔案編碼被當成 ANSI | .ps1 只寫英文 |
| bash 長 heredoc 內含引號導致 `unexpected EOF` | 單引號衝突 | 改寫成 Python 腳本檔再執行 |
| GitHub 範本下載到 849 MB 斷線、壓縮檔損毀 | 單次下載逾時 | `curl -C -` 斷點續傳＋迴圈重試，完成後才解壓 |
| `rm -rf ../web-build/*` 被安全檢查擋下 | 刪除萬用字元路徑 | 不刪，直接覆蓋匯出 |
| Google Drive 資料夾檔案無法用瀏覽器上傳 | 工具只允許讀 session 資料夾 | 先複製到 scratchpad 再上傳 |

### Tripo
| 症狀 | 原因 | 解法 |
|---|---|---|
| 匯出後 Downloads 找不到 GLB | Chrome 預設下載位置被設成專案資料夾；之後又以 `.tmp` 存在 Downloads | 兩處都檢查；用 GLB 內嵌貼圖名稱辨認檔案 |
| 連續匯出後半段沒下載 | Chrome 封鎖同站多檔下載 | 請教師允許 studio.tripo3d.ai 多檔下載 |
| 一個 .tmp 被誤認成珍奶怪（其實是車站） | 用三角面數猜檔案不可靠 | 一律讀 GLB 的 images 名稱核對 |
| 匯出時重複點擊產生 `(1)` 副本 | 匯出慢、重點了一次 | 匯出後清掉副本 |
| 模型預設 200 萬面、Sharing Only | Tripo 預設值 | 每次生成前改 Polycount 5000、Private |
| 中文招牌字錯（「水心之初」→「冰心之助」） | AI 模型寫不好中文 | 中文字一律在 Godot 用 Label3D／TextMesh 疊上 |
| 免費生圖額度用完 | Tripo 每日限額 | 改用 ChatGPT API 生參考圖再上傳 |
| 主角 195 萬面、無骨架只能跳 | Tripo 模型是靜態雕像 | Retopology 減面 → Rig → walk／idle |

### Godot 與畫面
| 症狀 | 原因 | 解法 |
|---|---|---|
| 畫面太亮、像玩具盒 | 環境光與色調預設 | 加天空、遠山、Filmic 色調、調低環境光 |
| 第一人稱鏡頭看自己的腳 | 鏡頭目標用到 Ken 自己的位置 | 另存 `battle_center` 當鏡頭目標 |
| 怪物被建築／樹擋一半 | 只用中心點判斷遮擋 | 改用物件實際外框與「眼睛→怪物頭身腳」線段相交 |
| 怪物腳陷進馬路 | 路面高 0.2 m，模型放在 y=0 | 統一 `FOOT = 0.22` |
| Ken 穿過汽車 | 汽車壓到 Ken 走的中線 | 汽車移到馬路邊緣 |
| 開場鏡頭卡進車站 | 開場朝向使鏡頭在建築內 | 開場面向車站＋鏡頭碰撞時拉近 |
| 魔王在遠處很小 | 魔王站得遠、FOV 大 | 攻擊時縮 FOV 拉近（魔王 30°） |
| 答題面板擋住怪物 | 面板佔滿畫面 | 戰鬥時面板只佔下半部、半透明 |
| `Trying to assign previously freed instance` | 怪物被刪時攻擊協程還在跑 | 每個 await 後檢查 `is_instance_valid` |
| 自動測試「沒按也攻擊」誤判 | 測試腳本流程與遊戲協程互相干擾 | 測試等 `busy` 結束再進下一關 |

### 網頁版與 iPad
| 症狀 | 原因 | 解法 |
|---|---|---|
| 中文在網頁版會變方框 | 網頁不能用系統字型 | 打包 Noto Sans TC 子集 |
| 遊戲檔 160 MB | 同時含電腦與 iPad 兩種貼圖格式 | 只給 iPad、貼圖上限 1024 → 約 54 MB |
| 內建瀏覽器測試時動畫停住、題庫讀取停在某個 % | 分頁沒顯示時頁面被暫停（讀題庫也靠遊戲每格更新） | 顯示預覽窗格再測；看伺服器紀錄確認檔案都有被要求 |
| iPad 讀題庫很慢、3 個聽力圖讀不到、錯誤訊息有方框 | 一次抓 95 個小檔；內建中文字型是加錯誤訊息前做的 | 素材合成一個 `bank-<雜湊>.pak`、自動重試 3 次、重做內建字型（2026-10-22） |
| pak 設 no-cache 後下載超慢 | Firebase CDN 不快取 no-cache 的檔，每次回源站 | 檔名加內容雜湊、設長期快取 immutable |
| 教師給的 .mp3 遊戲讀不出來（Failed to decode mp3） | 檔案其實是 WAV，只是副檔名寫 .mp3 | `build_mission.py` 檢查檔頭，不是 MP3 就用 ffmpeg 轉（2026-10-22） |
| 聽力題正解全都在 A | docx 第一欄放正解，遊戲不會打亂選項 | 轉題庫時用 ANS_POS 把正解平均放在 A／B／C |
| 新任務換 iPad 不能接著玩 | Firestore 規則只認 `ershui-3d-quest` | 規則改成接受 `ershui-3d-quest-<代號>`；新 3D 任務照這個格式取代號 |
| 部署報「Failed to get Firebase project」 | 沒指定帳號 | 指令一定加 `--project g6-english-online-learning --account u9431818@gmail.com` |
| iPad Safari 沒聲音 | Safari 要使用者先點畫面 | 提醒學生進遊戲先點一下 |
| 攻擊時明顯卡頓（70–94 ms） | 第一次畫特效要編譯著色器、產生字型圖；每擊新建材質 | 開場「準備中」預熱所有特效、文字、音效；材質共用；iPad 粒子減半放大 |
| 每隔 1–2 擊微卡 | 特效物件 1.6 秒後被刪除，剛好撞到下一擊 | 物件池：開場建好、攻擊時只重複使用（**iPad 上仍待確認**；若靜音後不卡，下一步預先解碼音效） |
| 電腦測不出 iPad 卡頓 | 電腦效能遠高於 iPad | 用 `--perf` 量「最長一格」比較改版前後，最終仍以 iPad 實測為準 |

| 情況 | 學到的做法 |

| 部署 | 預覽頻道給教師 iPad 實測；教師明說「部署正式站」才上正式站 |

## 四、下次改版的標準步驟（速查）

1. 改 Godot 程式或素材。
2. 有新中文字 → `python -I tools/build_cjk_font.py C:/Users/User/Godot/dl/NotoSansTC.ttf`。
3. 有改題庫 → `python -I tools/build_quiz_data.py`，再 `python -I -X utf8 tools/build_mission.py --mission ershui-3d-quest --unit "二水 3D 英語闖關 HWG5 R1" --title "Ershui 3D English Quest" --questions data/questions.json --plan data/quiz_plan.json`。**只改題庫就不用重新匯出遊戲**，跳到第 6 步。
4. 測試：`-- --test --bank=<site>/public/ershui-3d-quest/bank`（看截圖）、`--shots`（13 地點）、`--perf --mobile`（攻擊幀時間）。
5. 改了遊戲才匯出：`Godot_console.exe --headless --path . --export-release "Web" <site>/public/quest3d/index.html`。
6. `cd site && npm test`。
7. 預覽：`firebase hosting:channel:deploy ershui-preview --only hwg5-clock-tower --project g6-english-online-learning --account u9431818@gmail.com --expires 7d` → 教師 iPad 實測。
8. 教師同意 → `firebase deploy --only hosting:hwg5-clock-tower --project g6-english-online-learning --account u9431818@gmail.com` → curl 讀回確認。
9. 收工：commit＋push（目前尚未 commit）。

# RDQ 需求規格：字母聽寫播放卡住修復

## 一句話任務
iPad 上按「先聽目標字母 3 次」後，不論音檔是否順利播完，一定能進入手寫。

## 已確認
- 2026-11-02 課堂：7 台 iPad、14 位學生（7 組），約 4 台卡在「正在播放 3 次」，無法手寫
- 原因：playOnce() 只等 ended 事件，沒有逾時，也沒處理 pause／abort／error；iPad Safari 不送 ended 時就永遠卡住
- 1A：播放卡住 → 自動解鎖手寫，按鈕回到「再聽一次」
- 2A：播放 8 秒後出現「我聽完了，開始寫」按鈕
- 3A：先部署預覽頻道，老師用 iPad 試過再上正式站
- 只改前端播放流程，不動 AI 辨識與後端

## 已採納建議
- ① 每個字母共用一個已載入的音檔，不重複下載
- ② 手寫解鎖後，再聽一次不會重新鎖住手寫板
- ③ 按鈕顯示「第 1／3 次」
- ④ 模擬卡住、打斷等情況做自動測試

## 待確認假設
- 每次播放逾時 = 音檔長度 + 2 秒（讀不到長度用 6 秒）；逾時視為播完，不跳警告視窗
- 音檔預載 4 秒沒有回應就視為可播放（iPad 常不預載）

## 驗收條件
- [x] 模擬 play() 不出聲：11 秒內自動解鎖（本機 Chromium）
- [x] 模擬 play() 永不回應：9 秒出現「我聽完了」，按下立即解鎖
- [x] 模擬播放被打斷：約 3 秒內解鎖；重聽時手寫板不再上鎖
- [x] 正常播放：完整 3 次、間隔 1 秒，6 秒解鎖
- [ ] 老師用 iPad 在預覽網址走完一題 → 再上正式站

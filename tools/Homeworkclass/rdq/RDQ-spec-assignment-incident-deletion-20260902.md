# RDQ 需求規格：作業與課堂事件刪除

## 一句話任務
在教師後臺加入可追溯的作業作廢與課堂事件刪除流程，並修正課堂事件選填備註造成的 Firebase 儲存錯誤。

## 已確認
- 僅已登入的單一教師可操作；學期內任何日期的紀錄都可處理。
- 作業按「刪除」後不刪原作業，而是新增作廢狀態並從「已出的作業」等作用中畫面排除。
- 作業的繳交、未交及補交事件全部移入教師可見的 30 天回收區，再永久清除。
- 課堂事件移入同一個 30 天回收區，立即從作用中紀錄與需關注分數排除，期滿永久清除。
- 回收區只供教師查看，不提供還原；刪除不填原因，只顯示簡單確認視窗。
- 永久保存的最小稽核只含資料類型、原始 ID、刪除時間與刪除筆數，不保存原內容或原因。
- 一併修正已選座號但備註留空時送出 `note: undefined` 的錯誤；選座號後文字內容維持選填。

## 待確認假設
- 刪除由受 App Check 與教師身分保護的 callable Cloud Function 以單一原子操作執行，瀏覽器不可直接逐筆刪除。
- 30 天以伺服器刪除時間計算，使用 Firestore Timestamp `purgeAt` 與 TTL；TTL 實際清除可能不是精準到期秒數。
- 回收資料不進入一般 CSV／XLSX／列印／JSON 報表；一般報表只呈現仍有效紀錄。

## 已採納建議
- 先完成本機、Emulator、匯出與響應式測試；Firestore Rules、Functions、TTL 與 Hosting 正式部署另行逐項授權。

## 本次不納入
- 刪除／作廢原因、影響筆數預覽、回收資料還原及作廢作業恢復。
- 由 Codex 自動刪除截圖中的正式作業；功能部署後仍由教師本人確認操作。
- 未採納建議①至④的其他稽核、報表與恢復延伸功能。

## 一段式需求規格
在 **Homeworkclass** 教師後臺中，於右側「已出的作業」每筆卡片及「課堂情況／已登記事件」每筆卡片加入至少 44×44 px 的刪除按鈕與簡單確認視窗。作業刪除以 append-only 作廢事件實作，原作業保留但不再出現在作用中作業、繳交選單及一般報表；所有關聯 submission events 由受保護的 callable Cloud Function 原子移入教師限定的回收集合並從作用中集合刪除。課堂事件以同一後端流程移入回收集合並從作用中集合刪除，使需關注分數立即重算。回收資料寫入伺服器刪除時間與 **30 天**後的 `purgeAt`，不提供還原，期滿由 Firestore TTL 永久清除；另寫入不含內容與原因的最小稽核。Firebase 寫入前必須省略 undefined 欄位，使已選座號且未填備註的課堂事件可正常儲存。所有正式 Rules、Functions、TTL 與 Hosting 變更均須在本機及 Emulator 驗證後另行取得教師授權。

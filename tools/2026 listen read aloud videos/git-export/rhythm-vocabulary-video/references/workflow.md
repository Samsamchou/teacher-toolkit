# 工作方法 / Workflow

## 來源與配對

先讀本次專案規則、正式基準與來源。`rhythm_video.py inventory`以數字檔名排序，輸出SHA與候選字詞；視為待核對資料。先看圖，排除缺圖、重號、檔名與內容不符。掃描件走images.md；現成完整圖卡不必重裁。

載入正式profile時核對黑板及鼓聲資產。正式背景是參考片第0格，其他試抽格曾有殘留圖卡；沿用已接受背景不必每案重抽。鼓聲來自原參考片Demucs分離結果，保留來源記錄，原片人聲不作重製素材。未獲選定的替代背景或節奏不能靜默替換。

## 語音與時間軸

先查已接受語音庫。既有同詞、聲線、速度及錨點可複用；圖片不同不代表要重新生成聲音。新字詞走audio.md，保留原始API音、正常速度整理版、0.85版與安全紀錄。已變慢的音檔不可再做一次0.85。

由實際語音長度、前導音節、尾音及鼓聲攻擊點排程。四拍可放老師第1拍／兒童第3拍；八拍放第1／第5。不足再增加整小節，不能裁掉詞尾或加速塞入固定時長。每輪起始與中間總覽沿用整拍時間，尾段總覽約3秒。

新聲線或新字詞先交代表試片與清楚節拍檢聽音，再依教師確認完成。若新片只重用已接受的詞、聲線、語速、節奏與樣式，沿用真實接受紀錄即可，不重新要求挑選A/B。是否需要額外圖卡預覽，按新圖裁切與配對的不確定性判斷。

## 畫面與編碼

使用Pillow逐格合成，不需要影片生成API。1920×1080背景、約596px朗讀圖卡、白色英文、入場緩動及衰減搖擺均在renderer中。每輪8張總覽用4欄×2列，上列前4張、下列後4張，總覽圖卡約290px；每輪9張維持3欄×3列及約205px圖卡。片頭、兩輪切換和尾段均按當輪實際張數排版，32張兩段也各按8張排。

配對檢查必須包括字幕大小寫，一般單字全小寫，Chinese、English首字母大寫，PE維持縮寫。inventory保留source_word並提供正規化顯示字；preflight拒絕未修正的MUSIC、SCIENCE、chinese等設定。其他教師指定的專名或縮寫可用display_case_exceptions記錄。此規則同時適用總覽及逐張朗讀字幕；原圖內的手寫、星期與著色維持原樣。

FFmpeg以libx264、preset fast、CRF18、yuv420p、30fps編碼；AAC192kbps／48kHz，faststart。這些是正式模板的可重現參數；新題材片長由排程決定。

保留原voice/background/click分軌，正式mix在說話時降低背景。新版只修改畫面時，先建立新計畫，再以`render --reuse-audio PREVIOUS_MP4`；工具要求音訊指紋與前版檔案SHA相同，不符合就停止，不將錯的聲音混入新片。

視覺規則更新後須另存新job，不直接續用舊規則產生的影片。visual_policy_version用來阻止舊版3欄八圖總覽被誤判為新版可直接複用；舊音軌仍可經指紋核對後複製。

## 分段與雲端

32張各段單獨渲染、QA、教師確認；`merge --acceptance ACCEPTANCE_JSON`依1→2合併。合併會處理每段AAC起始padding而非盲目拼接；仍需量測接點前後聲音時碼、無空白／靜音斷裂、總長及完整解碼。不能用兩段已驗收推論合併檔也已驗收。

雲端僅使用本次明確指定的Drive同步目錄／目標。Drive讀取可用時以list_folder尋找影片，metadata核對名稱、格式及bytes。一般文字搜尋未找到MP4時不代表檔案不存在；直接列已知父資料夾。檔案權限保持既有設定。

目前範例基準是G槽2026 listen read aloud videos專案的FORMAL_BASELINE.json；該檔只鎖定正式影片與人類接受狀態，並非任何新影片的自動接受授權。

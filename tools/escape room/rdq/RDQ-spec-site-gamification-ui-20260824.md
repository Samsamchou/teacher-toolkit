# RDQ 需求規格：二水水路守護站遊戲化改版

## 一句話任務
將現行 HWG7 U01+02 網站改造成二水水路守護站 HUD 風格，使用 Comic Relief 英文字型、敘事化進度與不中斷任務的中英情境引導。

## 已確認
- 全站學生畫面採「二水水路守護站 HUD＋日式動漫角色對話」；首頁、任務地圖、任務說明、題目、提示、回饋、獎勵與結尾皆遊戲化。
- 頂端改為 Energy 能量條、六座守護站圖示及六格任務物品欄；學生端不再顯示「主題題 x/18」與「必要節點 y/21」。
- 所有英文均使用本機自帶的 Comic Relief；中文使用易讀中文字型，混合語句需分開標記語系。
- 學生端不顯示 `U01-M2-Q3`、`節點 7/21`、Q 編號或其他內部代碼；內部 ID 繼續供續答、測試、教師報表與 CSV 使用。
- 21 個必經節點都加入一至兩行、永遠可見的簡短中文情境／任務目標；中文不得翻出答案或新增決定性線索。
- 既有 60 張圖片優先重用；技術／開發訊息移出學生任務流程，放入教師或測試資訊區。
- 五項 RDQ 建議全部採納：本機字型、內外部 ID 分流、中英情境資料欄位、技術訊息分流、輕量動畫與減少動態效果。
- 題目證據改成線索掃描器、選項改成遊戲答案卡、提示／答對／再試使用既有水水姿勢；系統 emoji 改成一致的 SVG 圖示。


- Energy 保留精確數值；能量條以 0–100 呈現填充，90 以上為滿格發光，超過 100 仍顯示真實數值且不改變既有計分公式。
- 六站只顯示站名、鎖定／目前／完成圖示，不顯示 Mission 1–6；A／B／C 選項字母保留，因其不是題號。
- 動畫以 180–450ms 的能量變化、站點解鎖、物品入槽與角色回饋為主；不使用阻擋閱讀的循環動畫，並遵守 `prefers-reduced-motion`。
- 教師登入與報表沿用同一色盤與元件，但以資料可讀性為先，不套用強烈遊戲特效。
- 本次先不新增 ImageGen 圖片；只有既有資產無法支援必要 UI 時，才另列缺件清單請教師確認。
- 1024×768 橫向採緊湊 HUD；圖片辨識子題使用滿寬三圖版型，避免沿用左右欄而使選項過小。

## 已採納建議
- Comic Relief WOFF2 與授權檔隨網站部署；所有英文由統一的英文文字元件或 `lang="en"` 輸出。
- 學生 DOM、替代文字與可見狀態移除技術題號；內部資料模型保持不變。
- 每個節點新增 `contextEn`、`contextZh` 與 `missionGoalZh`，並執行防洩題檢查。
- Firebase／TTS 開發提示只在教師／測試資訊區顯示。
- 觸控目標至少 48×48px，動畫不只靠顏色表達狀態，並提供減少動態效果。
- 使用 `100dvh`／安全區 fallback，補齊場景與終局 Retina `srcset`，避免 iPad Safari 工具列遮擋或高密度畫面模糊。

## 本次不納入
- 不改動 18 題正解、3 個圖片子題、節點順序、提示邏輯、Energy 計分公式或新／續 attempt 規則。
- 不在本輪完成正式 Firebase、六碼後端驗證、OpenAI 靜態 TTS、正式部署或 iPad 實機驗收。
- 不新增任務、角色、題目或大批圖片，也不重新生成已核准人物。

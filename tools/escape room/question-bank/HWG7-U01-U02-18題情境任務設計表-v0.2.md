## 4. 國家證據防洩題規則

1. 學生答題前欄位 `missionText`、`clueText`、`glossary`、圖片內文字、檔名與圖片替代文字，都不得出現該題正解國家的英文、中文、縮寫或國籍形容詞。
2. 國家證據只可由以下類型組合：無文字地標、食物、動物、城市景觀、無文字國旗。人物外貌、膚色與姓名不能作為國籍證據。
3. 每一國家題至少兩項互相支持的圖像證據；圖片本身不得印國名。
4. 題幹與答案選項可以依法呈現教材國名；「證據區」不可以先顯示答案。
5. 上線前同時執行文字正規化掃描、圖片 OCR 與人工視覺 QA；檢查正解、中文譯名、縮寫、城市名及替代文字洩漏。
6. 干擾選項必須語法合理，但至少和一條決定性線索衝突；不得靠長短、亮度、角色視線或特效猜答案。

## 5. 圖像化證據資料規則

每條虛構證據都使用以下資料關係：

```text
evidenceId → clueText／neutralAudioText → imageSpecId → imageAssetId（確認並產圖後才填）
```

- `clueText` 有英文時，旁邊必須有對應插圖或圖示，並有獨立點讀按鈕。
- 一張場景圖可以支援多條線索，但每條線索都要列 `supportedByImageIds`，不可出現孤兒文字。
- 產圖前只填 `imageSpecId`，`imageAssetId` 留空，不能用假檔案冒充完成。
- 圖片不得新增未核准文字、人物關係、旗幟或交通方式；不得讓學生不讀英文就能靠版面提示猜答案。
- 圖片子題的三張圖保持相同日式動漫風格、相同畫面重量與相同背景複雜度，且不得印英文或中文答案。

## 6. 全站英文朗讀、OpenAI TTS 與受控 SSML

### 6.1 覆蓋範圍

凡畫面上出現英文單字或句子，都必須登錄於 `englishSegments`，包括：Mission English、難字英文、人物卡英文、虛構證據文字、情境問題、A／B／C 選項、提示、答對解析、狀態標籤、按鈕及結尾文字。不得在 UI 寫入未登錄且沒有音訊的英文。

每段至少保存：

```json
{
  "segmentId": "seg-u01-m1-q1-prompt",
  "audioId": "aud-u01-m1-q1-prompt",
  "displayText": "Where are you from?",
  "plainText": "Where are you from?",
  "ssmlSource": "<speak><prosody rate=\"80%\">Where are you from?</prosody></speak>",
  "ssmlUsedAsApiPayload": false,
  "voiceRole": "narrator_m",
  "model": "gpt-4o-mini-tts",
  "voice": "cedar",
  "apiSpeed": 0.8,
  "ttsInstructions": "Speak clearly in friendly American English for elementary learners.",
  "sourceHash": "待產檔時計算",
  "filePath": "待產檔後填入"
}
```

### 6.2 兩個固定聲音角色

- `narrator_m／male_character`：暫定 OpenAI `cedar`，作為男性呈現的旁白與男生角色聲音。
- `female_character`：暫定 OpenAI `marin`，作為女性呈現的女生角色聲音。
- OpenAI 官方只提供 voice 名稱，沒有把 voice 正式標成男性或女性；以上是本專案的呈現角色，正式產檔前由教師試聽核准，之後全站只鎖定這兩個 voice。

### 6.3 SSML 技術實作界線

OpenAI Speech API 目前文件列出 `input`、`model`、`voice`、`instructions`、`speed` 等欄位，但沒有承諾原生解析 SSML。因此本案採「受控 SSML 編輯來源＋編譯器」：

- 所有句子保存完整 `<speak>` 根元素與核准標籤。
- `<prosody rate="80%">` 編譯為 API `speed: 0.8`，不再把網頁 `playbackRate` 設成 0.8，避免實際變成約 0.64 倍。
- `<break time="...ms"/>` 轉成分段音訊與固定長度靜音，確實保留停頓。
- `<emphasis>` 轉成分段及 `instructions`；`<sub alias>` 轉成實際朗讀文字。
- 未列入 allowlist 的標籤阻擋產檔；原始 SSML 標籤不直接送進 API，也不宣稱 OpenAI 原生支援 SSML。

正式流程為：`SSML 驗證 → 編譯成 plainText／instructions／speed／分段停頓 → 產生靜態音檔 → 人工發音 QA → 網站播放`。

其他發布阻擋條件：

- 國名、scooter、metro、縮寫、問句語調與連音需逐段人工試聽。
- iPad Safari 必須由學生點擊後播放；播放新段落前先停止上一段。
- API 金鑰只可放受控後端或安全的離線產檔流程，不得寫進瀏覽器程式碼。
- 介面固定揭露：「本網站英語音訊為 AI 生成語音，非真人錄音。」
- 每個正式音檔保存 model、voice、speed、instructions、source hash、音檔 SHA-256 與 QA 狀態。

官方技術依據：

- [OpenAI Speech API reference](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create)
- [OpenAI Text to speech guide](https://developers.openai.com/api/docs/guides/text-to-speech)

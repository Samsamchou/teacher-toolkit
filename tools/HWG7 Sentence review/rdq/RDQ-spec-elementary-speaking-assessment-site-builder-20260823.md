# RDQ 需求規格：國小英語口說評測網站建置技能

## 一句話任務
建立一個與彈珠遊戲完全分離、可套入新題庫並重建獨立 Firebase 口說評測網站的 Codex skill。

## 已確認
- 學生採單人制，只輸入學號後完成指定題目；學號格式在每次建站前確認。
- 教師以 Google Docs／Markdown 標準表格提供題庫，skill 驗證後產生版本化 JSON。
- 題型 1 顯示並朗讀目標句；題型 2 顯示並朗讀問句，但學生只錄答句，問句不進逐字稿或分數。
- 每次開局隨機決定起始題型，之後題型 1／2 嚴格交替；各型內隨機、同次不重複且各抽相同題數。
- 每次建站前確認題庫總數、每次評測題數及全站共用過關分數；評分公式固定且版本化。
- 每題最多 3 次有效嘗試，系統失敗不扣次；保留該題最高分，三次未達標仍記錄未達標並進入下一題。
- 題型 1 目標句與題型 2 問句都使用預先產生的靜態美式 AI 示範音檔，學生播放時不即時呼叫 AI。
- 教師後台顯示每位學生逐題最高有效錄音分數與最終總平均；必須完成全部指定題目才計算平均。
- 每個新網站使用獨立 Firebase 專案；先完成本機建置及安全驗證，收到指定專案的明確授權後才建立／部署正式資源。
- 新 skill 名稱固定為 **elementary-speaking-assessment-site-builder**，安裝於既有 Codex skills 目錄，保留自動辨識並支援明確呼叫。
- 固定評分公式為「準確度 50%＋完整度 30%＋流暢度 20%」，並保留題型專屬子規則。
- 最終平均使用所有指定題目的 bestScore 算術平均並四捨五入為整數；未完成時顯示「—／尚未完成」。
- 錄音預設保存 30 天。
- 網站名稱、學號格式、題數、門檻、TTS 聲音／速度、保存期限與 Firebase 目標都在每次建站前重新確認。
- 分數標示為教學練習分數，不宣稱為正式標準化語言能力測驗。

## 已採納建議
- 納入乾淨且版本化的獨立 starter、教師題庫確認閘門、三次有效嘗試與最高分、私有錄音／教師短效權限，以及本機／專案／計費／部署／Secret 分層授權。

## 本次不納入
- 彈珠遊戲、雙人同機、正式標準化語言能力認證、未確認即自動部署或啟用計費，以及打字／排序／配對等其他題型。
- 本次 RDQ 階段不建立 skill、網站、Firebase 專案、API key 或正式資料。

## 一段式需求規格
建立 **elementary-speaking-assessment-site-builder**，內含無彈珠依賴的版本化全端 starter、Google Docs／Markdown 題庫表格契約、題庫驗證與 JSON 產生流程、固定且版本化的口說評分、靜態美式 AI 音檔產生流程、單人學生錄音介面、教師後台、Firebase Functions／Rules／私有錄音與四層 QA。每次呼叫先讀最新版模板並建立設定卡，向教師確認網站名稱、學號格式、題庫數、每次題數、共用過關分數、TTS 與保存期限；題型 1／2 由隨機起始後嚴格交替，題型 2 只評答句；每題最多三次有效嘗試並保存 bestScore，完成全部指定題目後才顯示總平均。先交付本機成果與驗證證據，建立獨立 Firebase 專案、啟用計費、設定 Secret 與正式部署各自等待明確授權。

## 驗收條件
- [ ] 技能套件、starter、題庫模板、references 與必要 scripts 結構完整，官方 validator、內部連結及敏感資料檢查通過。
- [ ] 以一份隔離範例題庫完成本機 forward test：兩型等量、隨機起始、嚴格交替、無重複、雙類型 TTS 與答句-only 評分均通過。
- [ ] 學生可完成錄音、三次有效嘗試、未達標續題與完整評測；教師端逐題 bestScore、最高分錄音及完整後總平均計算正確。
- [ ] Firebase／AI 安全、指定桌機與 iPad 橫式 QA、模擬與真機限制、分層授權及未部署狀態均有可查證紀錄。

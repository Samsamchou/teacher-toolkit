## 1. 已確認的網站目標

製作一個供英語程度接近 CEFR A1 的國小學生使用的口說練習網站。學生依圖片完成朗讀或問答錄音；後端以 OpenAI 語音轉文字取得逐字稿，再由固定程式公式計算準確度、完整度、流暢度與總分，最後提供最多兩句、適合兒童理解的繁體中文口說提醒。

本網站提供「學習練習分數」，不宣稱為正式語言檢定、音素鑑定或 Microsoft Pronunciation Assessment 的替代品。

### 已確認題庫

- 共 13 題：題型 1 共 7 題，題型 2 共 6 題。
- 出題順序固定為 `1, 2, 1, 2, 1, 2, 1, 2, 1, 2, 1, 2, 1`。
- 第 13 題正式句為 `She would like some salad.`。
- 題型 2 已列出的短答與完整答句都算滿分可接受答案。
- 問句不做發音難字與語調分析；朗讀句和答句的發音目標、難字、重音、分組、語調與連讀資料用於評分解釋及學生提醒。
- `a1-v1` 不把 STT 誤認成音素評量：重音、語調及連讀不直接產生數字扣分。

## 2. 建議的整體架構

```text
學生瀏覽器
  ├─ 題目圖片、題幹與錄音介面
  ├─ MediaRecorder 錄音
  ├─ Web Audio 音量監測與自動停止
  └─ Firebase Auth 學生身分
          │
          ├─ 上傳真實格式音檔至 Firebase Storage
          └─ 呼叫 Firebase Cloud Function 評分
                    │
                    ├─ 驗證學生、題目與音檔
                    ├─ OpenAI STT 取得英文逐字稿
                    ├─ 固定程式執行文字對齊與 a1-v1 公式
                    ├─ 選出一個最重要的改善項目
                    ├─ OpenAI 改寫兒童版提醒
                    └─ 寫入 Firestore 成績及錄音路徑

教師後台
  ├─ 教師安全登入與 teacher 權限
  ├─ 日期 → 學生 → 題目／嘗試紀錄
  ├─ 分數、逐字稿、原始數據及錄音播放
  └─ 指定學生＋日期的軟刪除／永久刪除與稽核紀錄
```

### 技術選型草案

- 前端：Vite＋TypeScript；介面元件可採輕量 React，避免把整站塞在單一 HTML。
- Hosting：Firebase Hosting。
- 身分：Firebase Authentication；實際學生登入方式待 RDQ 確認。
- 資料：Cloud Firestore。
- 錄音：Firebase Storage，保存真實 MIME 與副檔名。
- 後端：Firebase Functions v2，區域預設考慮 `asia-east1`，正式值須核對目標專案。
- AI：OpenAI STT 與兒童版提醒；金鑰只放 Firebase Secret `OPENAI_API_KEY`。
- 測試：前端單元測試、Firebase Emulator 規則測試、跨裝置端到端測試、部署後 smoke test。

既有 Firebase 口說網站的 `transcribeSpeech`、`practiceResults`、日期優先教師後台、Teacher Custom Claim 與 Secret Manager 可作架構參考；不得直接沿用舊專案 ID、App ID、網址、Function URL 或資料路徑。

## 4. 題庫資料化計畫

### 4.1 每題資料

將教師確認稿轉為 `questions.json`，至少包含：

- `questionId`、顯示順序、題型及單元分類。
- 圖片路徑與正式替代文字。
- 題型 1 標準朗讀句。
- 題型 2 問句、所有滿分答案版本及縮寫正規化規則。
- 每個答案版本自己的核心欄位、句型欄位與 `Na`。
- 發音目標字、發音難字、重音字、語調、分組及連讀位置。
- `rubricVersion: "a1-v1"`。

### 4.2 自動驗證

- 題目 ID 不重複且恰為 13 題。
- 題型順序恰為 `1,2,1,2,1,2,1,2,1,2,1,2,1`。
- 每個圖片路徑存在；圖片檔數與題庫引用關係可核對。
- 每題都有必要句子、答案欄位及分析資料。
- 所有答案變體均由教師確認；短答使用自己的欄位與 `Na`，不得被完整答句的欄位扣分。
- 前端不內含教師密碼、OpenAI 金鑰或秘密設定。

### 4.3 仍待補齊

- `They’re his caps.` 的所有格人物是否確實為 `his`。
- 題目所屬單元、冊次或分類。
- 13 題圖片的正式替代文字。
- 發音分析是否完全符合教師課堂使用的示範方式。

完成這四項前可以建立介面與測試資料，但不應鎖定正式題庫版本或部署給學生使用。

## 5. 學生端流程

### 5.1 進站與身分

1. 進入活動首頁。
2. 依 RDQ 確認的方式取得學生身分，例如活動碼＋座號或正式帳號。
3. 顯示麥克風與錄音資料說明。
4. 第一次按錄音時才請求麥克風權限。
5. 逐題進行；題型 1 與題型 2 依固定順序交替。

### 5.2 每題畫面

- 圖片及替代文字。
- 清楚的題型指令。
- 題型 1 顯示朗讀句。
- 題型 2 顯示問句；有指定架構時顯示填空提示。
- 錄音、錄音中、處理中、結果、重試等明確狀態。
- 觸控目標適合 iPad 與手機，不依賴滑鼠右鍵或 hover。

### 5.3 每題結果

- AI 聽到的逐字稿。
- 正確、說錯、漏念及多說字的顏色＋文字／圖示標記。
- 準確度、完整度、流暢度與總分。
- 最多兩句口說小提醒。
- 播放本次錄音與「再試一次」。
- 不顯示「音素準確度」等未經驗證的名稱。

### 5.4 進度

- 顯示目前題數與已完成題數。
- 無效錄音不算完成、不給 0 分，直接要求重錄。
- 是否允許跳題、是否強制完成 13 題及是否保留跨裝置進度，待 RDQ 確認。

## 6. 跨裝置錄音模組

### 6.1 狀態機

```text
idle → requesting_permission → ready → recording
→ speech_detected → silence_counting → stopping
→ validating → uploading → scoring → completed

任一階段失敗 → retryable_error → ready
```

### 6.2 錄音規則

- 使用 `MediaRecorder.isTypeSupported()` 選擇真實可用 MIME。
- 優先 Opus WebM；iOS 依實際支援保存 MP4／M4A，不可只改副檔名。
- `mediaRecorder.start(250)`，每 250ms 收集非空片段。
- 由使用者點擊直接啟動或恢復 `AudioContext`。
- 音量高於 `max(15, 現場底噪 + 8)` 約 150ms 才判定開始說話。
- 開始後連續 4 秒低於門檻才自動停止。
- 題型 1：開口等待 12 秒、硬上限 30 秒。
- 題型 2：開口等待 15 秒、硬上限 40 秒。
- 停止後等待 `stop` 事件，再組合 Blob、檢查 Byte、可解碼性與有效語音。
- 結束、取消與錯誤都呼叫每條 `track.stop()`。

### 6.3 一致性設計

前端音量監測主要控制自動停止；正式評分所需的逐字稿、單字對齊與可重算資料應由後端保存。每次嘗試保存音檔雜湊、逐字稿、評分輸入、`rubricVersion` 與音訊分析版本，避免同一音檔被重複提交後產生不同歷史結果。

## 7. 後端轉錄與評分流程

### 7.1 建議流程

1. 前端建立 `attemptId`。
2. 以已驗證的學生身分將音檔上傳到受限 Storage 路徑。
3. 呼叫 `scoreAttempt`，只傳 `questionId`、`attemptId`、實際 MIME 與錄音量測資料。
4. 後端驗證題目、身分、檔案大小、MIME、路徑與是否重複處理。
5. 後端從受信任題庫取得標準句與可接受答案；不相信前端傳入的答案。
6. OpenAI STT 只取得英文逐字稿，不把完整答案當強提示。
7. 進行文字標準化、答案版本比對與單字對齊。
8. 依 `a1-v1` 固定公式計算準確度、完整度、流暢度與總分。
9. 依固定優先順序選出一個 `primaryIssue`。
10. OpenAI 只改寫兒童版提醒；後端驗證長度、繁體中文與禁止用語。
11. 寫入 Firestore；回傳學生成績畫面。

### 7.2 冪等與可重現

- 建議以 `audioSha256 + questionId + sttModel + rubricVersion` 作處理鍵。
- 同一處理鍵再次送出時回傳已保存結果，不重複產生分數或費用。
- 歷史紀錄保存當時逐字稿、公式輸入、分數及版本。
- 新公式不自動改寫舊成績；重算需由教師明確觸發並保留原分數。
- AI 回饋失敗時仍保存固定公式分數，顯示暫時無法產生提醒。

## 8. 評分引擎實作順序

### 8.1 純函式優先

先以文字與固定時間數據建立不連網的純評分函式：

- 大小寫、標點、空格與已核准縮寫正規化。
- 最小編輯距離或同等的單字對齊，產出 `C`、`S`、`D`、`E`、`R`。
- 題型 1 準確度、完整度、流暢度及總分。
- 題型 2 問句／答句切分、核心欄位、句型欄位、完整度及 59 分上限。
- 短答與完整答句各自使用自己的滿分答案結構。
- 所有分數四捨五入為 0～100 整數。

### 8.2 發音分析的使用界線

- 目標字說錯或漏說只計一次，不因「難字」再次扣分。
- 難字前合理停頓依 A1 寬鬆公式處理。
- 重音、語調與連讀在 `a1-v1` 只用於教師示範及回饋文字。
- 未做可靠聲學分析時，不宣稱學生特定音素、重音或升降調錯誤。

### 8.3 單元測試矩陣

- 完全正確、漏字、替換、多說、重複與自我修正。
- 短答滿分、完整答滿分、核心答案錯誤、只有句型正確。
- 問句正確但答句錯誤時總分不超過 59。
- 開口前與尾端靜音不納入流暢度。
- 一次難字停頓只輕扣或不扣。
- 相同輸入與相同版本得到完全相同數字結果。

## 9. Firebase 資料設計草案

### 9.1 Firestore

```text
questionBanks/{bankVersion}/questions/{questionId}
practiceResults/{attemptId}
students/{studentUid}
teacherAuditLogs/{logId}
deletionJobs/{jobId}
```

`practiceResults` 至少保存：

- 穩定學生代碼／UID、台北日期、題目 ID、題型、嘗試次數。
- 標準句或所匹配的滿分答案版本、逐字稿。
- 四項分數與所有原始指標。
- `primaryIssue`、學生提醒、錄音路徑、MIME、Byte、SHA-256。
- `rubricVersion`、題庫版本、STT 模型、音訊分析版本、伺服器時間。
- 有效／無效、軟刪除狀態與刪除時間。

### 9.2 Storage

```text
recordings/{practiceDate}/{studentUid}/{attemptId}.{actualExtension}
```

- 路徑不含姓名。
- 學生只能上傳自己的新錄音，不能列出或讀取其他學生錄音。
- 教師須具備 `teacher` 權限才能讀取全班錄音。
- 永久刪除由後端同時刪除 Firestore 與 Storage。

## 10. 身分、安全與秘密

- OpenAI API 金鑰只存在 Firebase Secret Manager，不進瀏覽器、Git、題庫或 Firestore。
- 教師初始啟用密碼只在安全後端處理，正式使用前強制更改；前端不可出現明文比較。
- 教師登入成功後由後端核發 Custom Token／Custom Claim `teacher`。
- 教師登入錯誤 5 次鎖定 15 分鐘，閒置 30 分鐘登出。
- Firestore 與 Storage 規則同時檢查身分與資料歸屬。
- Cloud Function 驗證 App Check、Auth、題目 ID、音檔大小、MIME、頻率與重複請求。
- 設定每位學生、每分鐘及每日 AI 呼叫上限與帳務警示。
- Firebase Emulator 建立學生 A、學生 B、教師、未登入者四類規則測試。
- 部署前掃描前端建置產物，確認找不到教師密碼或 OpenAI 金鑰。

## 11. 教師後台

### 11.1 導覽

採日期優先：`日期 → 學生 → 題目 → 各次嘗試`。

- 預設 `Asia/Taipei` 今日日期，可切換過去日期。
- 左側顯示當日有有效紀錄的學生代碼、完成題數及當日平均。
- 當日平均使用每一題最高有效總分；無效錄音不納入。
- 右側顯示圖片、標準句／答案、逐字稿、四項分數、原始指標、提醒、時間、嘗試次數、版本及錄音。

### 11.2 刪除與稽核

- 桌機可有右鍵功能，但手機／iPad 必須有明顯刪除按鈕。
- 固定刪除範圍為「特定學生＋特定日期」。
- 確認視窗顯示 Firestore 筆數及錄音檔數。
- 預設建議先軟刪除，保存期限待 RDQ 確認；永久刪除再同步清除資料與錄音。
- 保存教師、時間、學生代碼、日期、筆數與動作結果等稽核紀錄。

### 11.3 可攜性建議

第一版建議提供日期或學生範圍的 CSV／JSON 匯出；這會增加少量開發與隱私檢查工作，但能避免日後更換平台時無法帶走教學紀錄。

## 13. 建置階段與關卡

### 階段 0：RDQ 與資料門檻

- 完成 RDQ 訪談及需求規格卡確認。
- 補齊題庫四項待確認資料。
- 確認 Firebase 目標、學生身分、保存期限、使用人數及裝置。
- 產出：已確認 RDQ 規格卡、正式題庫欄位表、風險清單。

### 階段 1：專案骨架與靜態學生介面

- 建立 Vite／TypeScript 專案、路由、樣式與 Firebase 開發設定。
- 以本機假資料完成 13 題交替、題型畫面、結果畫面與重錄流程。
- 不連 OpenAI、不寫正式資料。
- 關卡：桌機、iPad 尺寸與 Android 手機尺寸皆可操作。

### 階段 2：錄音概念驗證

- 完成 MIME 選擇、250ms 分段、音量監測、4 秒無聲停止、硬上限與 track 釋放。
- 保存本機測試音檔並驗證 Byte、可解碼性與播放。
- 關卡：iPhone／iPad 不出現 0-Byte；Android 短停頓不被提前截斷。

### 階段 3：固定評分引擎

- 完成題庫 JSON schema、文字正規化、對齊及兩題型公式。
- 使用固定逐字稿與時間數據跑單元測試。
- 關卡：同輸入重算一致，短答滿分，核心答案錯誤上限 59。

### 階段 4：Firebase 開發環境

- 建立或連接經確認的 Firebase 專案。
- 設定 Auth、Firestore、Storage、Functions、App Check、規則及索引。
- 使用 Emulator 驗證跨學生阻擋與教師權限。
- 關卡：未登入、學生 A、學生 B、教師四類權限全部符合預期。

### 階段 5：OpenAI 後端

- 教師親自設定 `OPENAI_API_KEY` Secret，不在對話或程式碼提供金鑰。
- 完成音檔驗證、STT、固定公式評分、回饋改寫、錯誤分類與冪等處理。
- 關卡：秘密掃描通過；AI 失敗時仍保留固定分數；重複請求不重複計費。

### 階段 6：教師後台

- 完成教師安全登入、日期篩選、學生平均、嘗試明細、錄音播放及資料清理。
- 關卡：未登入者不能讀取；教師可查詢但學生不能跨帳號讀取。

### 階段 7：整合與跨裝置測試

- 以合成或授權測試音檔完成完整流程。
- 實測桌機、iPhone／iPad Safari、Android Chrome 與共用 Wi-Fi。
- 測試網路中斷、拒絕麥克風、空白 STT、格式錯誤、超時、重複送出與播放器失敗。

### 階段 8：評分校準

- 準備約 20～50 份代表性錄音與教師人工分數。
- 比較自動分數與教師判斷，記錄偏差及調整理由。
- 若公式更動，升級為 `a1-v2`；不覆寫 `a1-v1` 歷史成績。

### 階段 9：正式部署與驗收

- 部署前再次核對 Firebase Project ID、App ID、網址、Functions 區域、資料路徑與秘密。
- 需取得教師明確部署授權後才發布 Hosting、Functions 及規則。
- 部署後執行登入、錄音、評分、報表、播放、刪除與安全 smoke test。
- 保存部署版本、Git commit、測試證據及操作 README。

## 15. RDQ 訪談前的紅燈決策

下列答案不同會直接改變 Firebase 架構、安全規則、資料模型或部署方式，必須在正式動工前確認：

1. 使用新的 Firebase 專案，還是連接既有專案／Hosting site。
2. 學生如何取得穩定身分，以及是否需要跨裝置接續進度。
3. 錄音、成績及軟刪除資料的保存期限。
4. 同時使用人數、最差裝置與學校網路條件。

其餘技術細節可在不改變教學目標的前提下採安全預設，並在 RDQ 規格卡列為待確認假設。

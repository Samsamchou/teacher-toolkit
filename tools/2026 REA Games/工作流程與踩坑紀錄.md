## 二、踩過的坑（依類別）

### REA 與研究
- **REA 不能拿來搬任天堂的東西**：它自己的免責聲明就排除「重製受保護的程式碼與素材」。能做的是學手感（數值），造型、名稱、音樂、關卡外觀全原創。
- **REA 6.7.0 打不開 Godot 4.7 的 `.pck`（PCK v4）**：`open_binary` 回 unsupported。改用 Python 讀 PCK 目錄列大檔（Ken 模型＋貼圖約 3 MB，佔 75%）。
- REA 要分析原生執行檔需要另裝 Ghidra＋Java；Hopper 不支援 Windows。這次不需要。
- faster-whisper 在這台的 PyAV 版本會報 `metadata_errors` 參數錯誤 → 先用 ffmpeg 轉 16 kHz WAV，再用 soundfile 讀成陣列餵進去。

### 公開 repo 與檔案
- **三支 YouTube 影片（830 MB）和逐字稿是別人的作品，不能推上公開 repo** → `tools/2026 REA Games/.gitignore` 排除 `YT/`、`transcripts/`、模型、圖片、音訊、字型、`.import`、`.godot/`。
- 網站 `public/jump3d/` 是匯出檔，用資料夾內 `.gitignore`（`*`）排除；Firebase 會略過 dotfile，不影響部署。
- Python 在 GDrive 上直接當本機伺服器很慢（bank.json 讀 15 秒）→ 測試時把需要的檔案複製到 scratchpad 再開伺服器。
- 透過 bash heredoc 跑含 `'''` 的 Python 修補腳本會被 shell 解析壞掉 → 改成先寫成 .py 檔再執行。

### GDScript／Godot
- **型別推斷**：`var x := 某個沒型別的值` 會 Parse Error（例如 `p.global_position`、`Array.filter()` 的結果、迴圈變數算出來的值）→ 明確寫型別（`var x: Vector3 = ...`）或用 preload 的腳本當型別（`var player: PlayerScript`）。
- **`await` 漏寫**：呼叫有 `await` 的函式要 `await`，三元運算子裡也不行（`await (a() if x else b())` 會報錯）→ 改成 if/else。
- **字串裡的 `\d` 是錯誤跳脫字元**，整支腳本會載入失敗（網頁版只看到灰畫面）→ 正規表示式用 `[0-9]`。
- **腳本有 Parse Error 時 Godot 不會結束**，背景測試會一直卡到 timeout → 先用 `godot --headless --path . --quit` 確認能編譯，再跑長測試；測試加短 timeout、每關分開跑。
- 單行 lambda 不能放 `if`（`func(k): if ...`）→ 拆成多行。
- `physics_frame` 訊號是在物理處理「之前」發出；計時器回呼後馬上 `await frames(1)` 讀到的可能是上一格 → 多等一格。
- 用 `--fixed-fps 60` 讓 headless 測試比真實時間快跑（13 關約 1–2 分鐘），但 `Time.get_ticks_msec()` 是真實時間 → 逾時改用 `Engine.get_physics_frames()`。

### 手感與關卡設計
- SM64 數值換算（1 單位 ≈ 0.0137 m）後，**跑步單跳就有 4.1 m 高、11 m 遠**，比直覺強很多 → 「二段跳高台」「三段跳高柱」「跳遠缺口」要用實測數字設計，而且要測「簡單的跳法過不去」：
  - 二段跳高台：升高 3.6 m（站著單跳 2.9 上不去，二段跳 4.5 上得去）
  - 三段跳高柱：升高 7 m（跑步二段跳最高約 6.2）
  - 跳遠缺口：14 m（跑步單跳約 11 m）
- 點一下跳躍鍵若立刻砍速度只有 0.7 m 高，iPad 小朋友會覺得跳不起來 → 起跳 0.08 秒後才算放開（約 1.6 m）。
- **Ken 斜斜頂著牆會整個卡住**（撞牆限速成「實際速度＋0.5」）→ 只在 `is_on_wall()` 時限速、留 3 m/s 餘裕讓他沿牆滑開。這是網頁實走才發現的遊戲問題。
- 魔王衝擊波測試偶爾失敗：隨機出現的星星剛好在 Ken 被放的位置 → 碰到星星開題目、整個遊戲暫停 → 測試時先把星星關掉。

### 美術
- 自訂 shader 的顏色在 iPad／截圖上偏亮偏淡；調光照（環境光、太陽）幾乎沒差 → 在 shader 最後 `ALBEDO = col * 0.8`。
- Kenney GLB 的貼圖是外部 `Textures/colormap.png` 相對路徑 → 模型和 `Textures/` 一起複製。
- 灰盒的棋盤格貼圖 `ImageTexture` 每關重建 → 材質依（種類, 高度）快取。

### 網站與學號登入
- 共用外框 `quest3d-app.mjs` 原本 iframe 寫死 `../quest3d/index.html` → 改成 `start(BANK, { game, bankBase, intro, meta, clearedLabel, credits })`，不帶參數時行為不變（舊任務 27 項測試全過）。
- 題庫共用 `../ershui-3d-quest/bank/`：build_mission.py 重新產生的 pak 雜湊不同，會讓學生多下載 9.5 MB → 只拿它的 `data.js`，題庫用舊的那份。
- `firebase.json` 快取規則要加 `jump3d`（wasm／pck 快取 1 天）；**反過來說，重新部署後瀏覽器可能一天內都拿舊檔** → 測試時用 `fetch(url, {cache:'reload'})` 強制更新。
- 預覽頻道用的是**正式 Firestore**：在預覽登入的學號會進教師後台 → 用測試學號（99901 已留一筆）。本機測試加 `?cloud=off`。
- Firestore 規則不用改：`ershui-3d-quest-jump` 符合 `^ershui-3d-quest(-[a-z0-9]{2,20})?$`。

### 瀏覽器實測
- **Claude 視窗縮小或被遮住時，內建瀏覽器每 2 秒只畫 0–3 格**，Godot 遊戲等於暫停（截圖也會逾時）→ 用 `requestAnimationFrame` 計數確認；要實走就要視窗開著。
- iframe 裡的 console 不一定讀得到 → 用同源 `iframe.contentWindow.console.log` 掛勾，或讀外框 localStorage 的進度。
- 用 JavaScriptBridge 讀外框網址（`window.parent.location.search`）判斷 autoplay；**正式站一律關閉**（只有 localhost 與網址含 `--` 的預覽頻道可用），避免學生加 `?autoplay=1` 自動答題。

### 自動闖關（autoplay.gd）本身的坑（不是遊戲問題）
- 落地還帶著 10 m/s 的速度就去做下一步 → 滑出 4–6 m 的小平台。→ 落地後放開搖桿等停下。
- 「落地後往中心帶」用全速推搖桿 → 越跑越快衝出另一邊。→ 改成放開搖桿。
- 走去起跳點太快（推 0.55 ＝ 7 m/s）→ 走出小石頭。→ 小跑 0.35、接近時 0.15。
- 一律全速助跑 → 跳過頭。→ 依「缺口＋半個平台」算需要的速度，失敗再試快一點或慢一點。
- 二段跳高台用「衝到邊緣起跳」會撞牆掉進縫 → 邊緣內側原地跳一下、落地馬上第二跳再往高台推。
- 空中只朝目標推 → 小方塊塔衝過頭 → 空中依「想要的速度 − 目前速度」修正（能煞車）。
- 三段跳每次都走回平台最遠角落 → 太慢 → 從高柱前 lead＋6 m 起跑。
- 題目在空中觸發（三段跳碰到星星）→ 主迴圈要先處理 `state == "quiz"`。

# 新地點小行星製作手冊（以彰化縣彰化市為例）

> 依據：二水小行星 v1–v4（2026-10-25 ～ 11-08）的實際做法與踩坑，詳細紀錄見 `工作流程與踩坑紀錄.md`、`HANDOFF.md`。
> 原則：**先查證、給老師核對，再蓋**；每一步都有「老師要做／確認什麼」。所有花錢的步驟先報價。

## 2. 地圖資料（OpenStreetMap）
1. `tools/fetch_osm.py`：改 `AREAS`（南,西,北,東），存成 `資料/osm/changhua-downtown-<日期>.json`。
2. `tools/build_osm_map.py`：改 `LAT0, LON0`（中心）、`RAD`、`STATION`、`TRI`（主要路口）、`OSM_FILES`、`REGIONS`（要不要第二塊街區）。
3. `PLACES`：11 個出題地點＋地標（id、中文名、單字、經緯度、kind）。
4. `SETS`：5 套路線，每套要包含全部 11 個單字（程式會檢查）。
5. 執行 `python -I tools/build_osm_map.py`，看輸出的建築數、店家放了幾家。
- 坑：同一條路名在 OSM 會分好幾段、車站前常有環狀路 → 已用「離已知門牌最近的一塊＋最長路線」處理（`shops_*.py street_chains`）。

## 2B. 同時抓 Google 地圖空拍圖（老師 11/08 指定：每家主要店的位置與門口方向都靠它定）
OSM 只有路與部分房子輪廓、門牌內插會差十幾公尺、也不知道正門朝哪裡；**主要地點與店家一律用空拍圖定位**。
1. **抓圖**：在 Chrome（老師已登入 Google）或內建瀏覽器開 Google 地圖「衛星」圖層，**同一個縮放等級**，沿每條主要街道一段一段截圖（每張涵蓋約 100–150 m，相鄰兩張要重疊一點），店名標籤要開著。也可以請老師自己截圖傳來（二水就是這樣）。
2. **存放**：`資料/aerial/<路名>-<日期>.png`，**只當對位參考**：不入庫、不放進遊戲畫面、不轉貼（Google 圖資授權）。
3. **對位**：每張圖找 **2 個以上錨點**（遊戲裡已有正確經緯度的點：車站、OSM 上有標的超商／藥局／廟），寫一個 JSON：錨點像素＋經緯度、要放的店的「店名標記像素」＋「正門前方的像素」（門口朝向哪條路）。
4. **換算**：`python -I tools/aerial_georef.py 資料/aerial/<名>.json` → 每家店的 lat、lon、正門朝向角度；同時印出錨點誤差，**超過 3 m 就換錨點**。範例：`資料/aerial/guangwen-20261108.json`（光文路兩家飲料店，比例 0.133 m／像素）。
5. **寫進資料**：地標與主要店家用 `lat/lon`＋`snap`（拉到路邊）或 `face`（指定朝向，例如面對車站前廣場）；同一側用 `side_ref` 確認。
6. **截圖給老師核對**：`ARRIVALS=1 ONLY=…` 拍每家店，和空拍圖並排看「同一側、緊鄰誰、門口朝哪」。

## 3. 街屋清冊（店家、地標）
1. 子代理上網查：沿主要街道的店家、診所、廟、公家機關（商號登記、衛生局名單、超商門市、美食文章、OSM）。提示詞範本見二水那次（`資料/街屋清冊-初稿-20261108.md` 的開頭說明）。
2. **老師核對**：哪家還開、名稱、連鎖用通用名（便利商店、超市、水餃店）、住家不放名字門牌。
3. 寫成 `tools/shops_<地點>.py`：`ANCHORS`（每條路 2–4 個已知座標的門牌）、`SHOPS`（店名、路、門牌、店面種類）、`LANDMARKS`。
4. 店面種類沿用 24 種圖（`tools/make_storefronts.py`）；彰化市若有新種類（例：銀行、書店、肉圓店）再加一格。
5. 主要店家先用 2B 的空拍對位放好；**老師再用 Google 空拍／街景指出還不對的店** → 用兩個已知點算比例，給經緯度＋「同一側」參考點（`side_ref`、`FRONT_FIX`、`FACE_TOWARD`）。

## 4. 地標 3D 模型（不花 Tripo 點數）
- Codex 畫參考圖 → Colab G4 Hunyuan3D-2 → 縮貼圖。步驟與腳本：`godot-ershui-planet/tools/colab_hy3d/README.md`。
- 每棟約 1 分鐘；一次開機做 8–10 棟約 10 個運算單位以內。
- 中文招牌：模型上是英文佔位字，用 `world.gd` 的 `BLD_SIGN`＋`SIGN_PLATE`（色板蓋住）寫中文；截圖 `SIGNS=1 ARRIVALS=1 ONLY=id` 對位置。
- 坑：模型太寬會互相重疊 → `LM_SIZE`／`BLD_SIZE` 照真實店寬（遊戲公尺＝真實 × 0.55）。

## 4B. 人物（Ken、吉祥物、新角色）
- 新角色或第一次讓角色做新動作前，先照 `tools/3D人物建模檢查清單.md`：雙手是否都張開（Ken、圳寶原檔右手是拳頭 → 用 `make_openhand.py` 鏡射，已有 `ken_openhand.glb`）、靜止姿勢是否 T-pose（`retarget.gd` 會先校正）、描邊用 0.3。

## 5. 大型場域（學校、公園、廟埕）
- 老師提供平面圖（例：疏散地圖）→ 子代理查照片 → 用 OSM 輪廓畫「俯視配置圖」給老師標註 → 再蓋。
- 程式：`build_osm_map.py` 的 campus 段（`SCHOOL_WAY`、`SCHOOL_ROLE`＝OSM 校舍 id → 用途、門的位置）＋`world.gd _campus`。**這段是二水國小專用，換學校要重填 id 與門的位置**。
- 跑道用程式搜尋「不碰任何校舍」的最大尺寸；大平面一律用 `_fill` 細帶鋪。

## 6. 聲音
- 題目語音：`tools/make_voice.py`（edge-tts 0.8 倍）。
- Listen and Guess：`data/listen.json`（8 個地點的情境句與答句，`place` 要換成新地圖的地點 id）→ `tools/make_listen_voice.py`。
- 環境音：`tools/make_ambience.py`（KIE Suno Sounds，每層 2.5 點，8 個地點約 100 點）；8 個地點相同的話**可以直接沿用二水做好的** `資料/ambience/final/`。
- 新中文字 → 重跑 `tools/build_cjk_font.py C:/Users/User/Godot/dl/NotoSansTC.ttf`；畫面文字不要用表情符號。

# 網站與 Firebase

## 啟動條件

只有教師明確要求某單元建立或擴充網站時才進入本流程。一般單元擴編不自動建立網站、資料庫或帳號系統。

先另做網站／安全／資料 RDQ，至少確認：

- 學生任務、教師功能、裝置與瀏覽器。
- 是否收集姓名、學號、作答、音訊、影像或操作事件。
- 保存期限、刪除方式、家長／學生告知與教師存取權。
- Firebase 專案、Hosting 站點、Functions、Firestore／Storage 路徑及部署目標。
- 驗收情境、真機測試及失敗備援。

## 可納入範圍

在地課程的互動教材、學生練習、教師紀錄與回看工具可納入。口說評測、五模式單字站及英語彈珠台應改用其專用 Skill，並沿用各自的安全契約。

## 實作順序

1. 先保存確認規格與資料模型。
2. 在本地建立或修改原始碼，使用測試資料。
3. 執行建置、單元測試、使用者流程與必要的 Rules emulator 測試。
4. 分別回報已驗證與未驗證項目。
5. 只有取得當次明確授權後，才設定 Secrets、修改公開 Rules、建立正式資源或部署。

## 安全邊界

- API key、教師密碼與服務憑證不得放在瀏覽器程式、Git、教案或交接文字；使用 Firebase Secret 或等效伺服器端機制。
- 公開 Rules、資料保存、正式部署、付費方案與外部發布都是獨立授權點。
- 登入與授權由教師親自完成，不要求或代填密碼。
- 不以本地建置成功代表已部署，不以雲端函式存在代表完整學生流程已驗證。
- 真實學生資料不作開發測試；測試資料要能清楚辨識並依規格清除。

# 二水在地課程擴編

以正式在地課程為主體，英語負責觀察、描述、口說與介紹；社會及綜合活動作支援。先保留來源與教師已確認決定，再逐節產出可教、可查、可重建的成果。

## 正式來源與安裝副本

- 唯一可編輯 Skill 來源是 `G:\我的雲端硬碟\teacher-toolkit\tools\localcoursesErshui\skills\ershui-local-curriculum-builder`。
- `C:\Users\User\.codex\skills\ershui-local-curriculum-builder` 只是安裝副本。不要直接修改；更新時只執行正式來源內的 `scripts/sync_skill.py sync`。
- 開始工作前，從專案正式來源執行 `scripts/sync_skill.py check`；若不一致，先說明差異。未獲得本次任務的寫入授權時，只檢查、不自行同步。

## 必走關卡

1. 讀取專案 `AGENTS.md`、`README.md`、`PROJECT_HANDOFF.md`、`WORK_LOG.md`，以及相關 `status: confirmed` RDQ。
2. 新正式單元先做完整 RDQ，產出一頁規格卡並等待教師明確確認。已確認的學期共通知識不重問。
3. 只從該年級、該學期、正式課名為「在地課程」的來源確認單元名稱、週次、節數、原目標、原活動、評量與頁碼／文字行號。
4. 建立「來源追溯與設計決定」，清楚區分原文、教師補充、保留、替換、新增及尚待確認。
5. 正式節數確認後，立即在單元根目錄建立同等數量的 `01_第1節/`、`02_第2節/`……；根目錄只留跨節索引、追溯／決定、全單元骨架與真正共用資料，各節正式成果及 `_work/`、`_qa/`、`_history/` 全部歸入該節。未開始節次放短 `README.md`，詳規讀取 [references/folders-and-deliverables.md](references/folders-and-deliverables.md)。
6. 教師確認設計決定後，建立全單元節次骨架；先確定在地活動與可見成果，再配置有直接功能的英語。
7. 從第一個尚未完成的節次開始，依序執行：詳案樣稿 → 教師確認 → 教材草稿 → 教師確認 → 製作與 QA → 下一節。
8. 到達教師確認關卡便停止，不預先製作下一階段。只有當次 `status: confirmed` RDQ 已明確記錄必要確認完成，並授權同一批次不中斷完成時，才依該 RDQ 繼續；此例外只適用該次範圍，不改變未來單元的預設確認關卡。已完成成果只稽核，不重做或覆寫。

每個活動名稱要讓教師能預測課堂；詳案需同時寫明教師操作、學生材料與行動、師生互動、時間及可見成果。每節保留課前教材、核心英語，以及有主標題的 Warm-up、Presentation、Production、Wrap-up。

四階段表格中的「主要活動標題」一律採兩層結構。第一層是可直接放入正式課程計畫、供審查委員判讀的標題；標題本身須同時說出核心內容、學生主要動作與教學目標，不可只用「闖關、解密、找回家、收束」等抽象或趣味名稱。第二層再用一至兩句寫明學生實際做法與可見成果。

詳案只要列出手作學習單、圖示板、資料句條、句型卡、操作卡、圖例卡、順序卡或出口票，教師確認詳案前就須逐項附「內容與操作草圖」，標出尺寸、人數、欄位／題目、學生書寫／連線／排序／指認位置、使用順序與教師答案。每個小題或區塊配置能解釋題意的角色動作或功能圖示，並視年級加入關鍵詞、字庫或句首提示；圖像不得只是裝飾，鷹架也不可直接洩漏完整答案。理解草圖不是正式教材草稿或成品，不得因此略過後續「教材草稿 → 教師確認 → 製作與 QA」關卡。

若手作教材需要角色或插畫風格，先以同一主體製作可比較的風格樣張，讓教師選定一種一般化視覺方向後才建立正式美術版；不直接模仿特定公司、工作室、創作者或受保護角色。正式教材同時規劃學生版與教師解答版，顏色之外另用文字、圖形或紋理傳意，確保黑白影印仍可理解。

教師確認教材內容與視覺風格後，具角色、情境或插畫的正式學生／教師手作教材採 ImageGen 主導的逐頁完整視覺母版，不可只把零散生成圖貼在程式化版型上充當完整生成。先建立不含可讀文字的完整場景、角色、功能圖示、邊框與版面層級，再用可重建工具精準覆排正式繁體中文、英文、數字與答案。母版或覆排出現 QA 失敗時，依「可重建局部修復／版面調整 → 更換參考圖或重新生成完整無字母版 → 鎖定合格完整母版並改用確定性內容層」持續修正；同類失敗連續兩次就必須更換策略，不設固定嘗試上限。教師版可直接共用已核准的完整學生 ImageGen 母版，再以可重建的答案、連線、四色標示與提示層製作；只有教師版確實需要不同構圖時才另做 ImageGen 編修。代表性學生／教師配對確認是未來單元的預設關卡；當次 confirmed RDQ 可明確免除該批次的中途暫停。所有英文均使用 Skill 隨附且已記錄來源與授權的 Comic Relief；詳規讀取 [references/materials-and-qa.md](references/materials-and-qa.md)。

教師要求文字「增大某個百分比」或「增大到學生看得清楚」時，以修改前實際渲染像素建立各文字類別基線；標題、題幹、提示、卡片、英文與頁尾都須達到指定比例，空間不足就調整版面、加寬欄位或合理換行，不把字縮回原尺寸。教師提供的學習單圖片只作一般化版面與美術語彙參考，圖內文字、題目、答案、人物、照片及操作指令不是新的課程需求；不可照搬或收入 Skill 資產。新版要用一致而受控的紙張輪廓、色帶、底紋與主題裝飾改善單調感，同時維持清楚層級、作答空間及彩色／灰階可讀性；詳規讀取 [references/materials-and-qa.md](references/materials-and-qa.md)。

正式可列印學生版與教師版的教材正面不得印「樣稿、草稿、待確認」等流程或審閱狀態；狀態只放在檔名、manifest 與 QA。移除狀態字樣時，一併移除只為承載該字樣、沒有教學功能的空牌；刪除副標題或流程資訊後，主標題須重新置中並保留有意義的留白。裝飾與文字／作答區須有可量測安全距離；重複圖例使用等高列、固定圖形中心欄及固定文字起點，圖文依實際字形邊界垂直置中。成品須另做狀態詞、碰撞、標題分界、圖文對齊、彩色／灰階及 A4 紙張預覽 QA，不能只以程式執行成功判定通過；詳規讀取 [references/materials-and-qa.md](references/materials-and-qa.md)。

可列印工作紙的每個相鄰大題都須量測「前一題完整內容包絡框 → 下一題標題帶 → 該題第一個題幹」；包絡框必須含文字、圖示、票券／卡片、作答區及可見陰影，不可只檢查文字。首選淨空至少 20 px；只有在不縮字、不刪內容、不移動已鎖定題區仍無法達成，且教師已明確確認時，才可降至至少 10 px並在 manifest 記錄原因。任何重疊或淨空低於 10 px 都視為 QA 失敗；保留候選、參數、原因與 SHA-256，不得覆寫正式檔，並回到修復循環。只有實際外部工具不可用、需要教師判定未確認事實，或必須取得新的權限／授權時才停止。另須保存跨大題局部放大、彩色、灰階與 A4 預覽證據；詳規讀取 [references/materials-and-qa.md](references/materials-and-qa.md)。

## 邊界

- 四年級上學期只作工作流程與 QA 範例，不把鐵道單元內容套進四下、三上或三下。
- 網站不自動啟動。口說評測、五模式單字站及英語彈珠台改用各自專用 Skill。
- 圖片正式生成、外部發布、Firebase Secrets／Rules／資料保存與部署、付費操作，都必須取得當次明確授權。
- 不把本機建置或測試說成已部署；不把 AI 圖或未人工核對的站名、路線、地標當成事實。
- 不修改原始課程檔、既有基線 Word、歷史 RDQ 或歷史對話。

## 完成與驗證

- 從正式來源執行 `python scripts/validate_workspace.py --root <專案根目錄> --require-confirmed-rdq <規格卡>`；此工具只讀。
- Word、試算表、PDF、圖片與網站須使用對應的文件或產品 QA 流程，不以檔案存在代替驗證。
- 讀回新檔，回報精確路徑、檔數／頁數、重要欄位、測試結果與限制；除非教師另行要求，不 commit、push、部署或更新 Obsidian。

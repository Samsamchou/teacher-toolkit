# 網站規格｜四年級上學期在地課程

## 1. 產品定位

本網站是二水國小四年級「在地課程」的數位學習入口。第一階段完整實作「坐火車趣集集」中的模擬線上購票活動，讓學生練習讀懂起點、目的地、日期、車次與摘要，並能發現起訖顛倒後修正。

網站是教學模擬，不連接臺鐵、不付款、不產生真實訂票，也不以真實時刻表作為可搭乘資訊。每個學生頁面均需顯示：

> 模擬教材，不可作為真實乘車或訂票資訊。

## 2. 使用者與完成成果

### 2.1 學生

- 不需登入。
- 只輸入五位數學號，例如 `40100`。
- 兩人共用一台 iPad：第一輪由 Operator 操作，Checker 逐項說 `Check from / to / date / train / time.`；第二輪交換。
- 完成六步購票與最終 SAMPLE 車票。
- 每步正確時看到 `You're right!`、綠色勾號、短動畫並聽到短音效。
- 六步加最終成功共七張過關畫面，合成一份七頁 PDF。

### 2.2 教師

- 從四單元首頁右上角進入教師後台。
- 使用 ChatGPT 登入；登入後還要通過 D1 `teacher_allowlist` 電子郵件白名單。
- 以單元、日期與學號篩選紀錄。
- 查看摘要、無聲操作重播、七頁 PDF，並可匯出或二次確認後刪除。

## 3. 資訊架構

### 3.1 四單元首頁 `/`

- 深藍色導覽列。
- 左側：「4年級上學期 在地課程」。
- 右側：「教師後台」。
- 四張單元卡：
  1. `unit.roundhouse`：扇形車庫。
  2. `unit.train-tickets`：坐火車趣集集。
  3. `unit.railway-reading`：閱覽鐵道風華。
  4. `unit.narrow-gauge`：介紹五分車與認識小火車鐵道。
- 本階段只有 `unit.train-tickets` 進入完整活動；其餘卡片顯示「教材建置中」或導向預留頁，不出現虛構練習。

### 3.2 購票練習 `/units/train-tickets`

- 首頁名稱：「火車線上購票網站—Buy Train Tickets Online」。
- 大尺寸學號欄，placeholder：「請輸入學號，例如40100」。
- 只接受五位數字。
- 主要按鈕：「Start／開始練習」。
- 不使用「購買」「付款」「送出訂票」等容易誤認的文字。
- 通過格式驗證後才向伺服器建立 attempt。

### 3.3 教師後台 `/teacher`

- 未登入者交由平台的 ChatGPT 登入流程。
- 登入後，伺服器讀取已驗證電子郵件並查詢白名單。
- 頂部工具列：單元、日期範圍、學號、同步狀態、登入帳號、匯出、安全登出。
- 左欄：依日期分組的 attempt 清單。
- 右欄：摘要、重播、PDF 三個分頁。

## 4. 視覺與版面

### 4.1 色彩

| 角色 | 建議值 | 使用方式 |
|---|---:|---|
| 深藍導覽 | `#17324D` | 導覽列與主要標題 |
| 票務藍 | `#1E6FA8` | 主按鈕、目前步驟、可操作欄位 |
| 暖橘強調 | `#F4A62A` | 路線、提示箭頭、可修正錯誤 |
| 成功綠 | `#2E8B57` | `You're right!`、勾號、通過邊框 |
| 背景 | `#F7FAFC` | 頁面背景 |
| 文字 | `#24313D` | 主要文字 |

色碼是兒童教學版建議值，只承接交通票務的層級感，不宣稱為臺鐵官方色碼，也不複製其商標、票面或完整介面。

### 4.2 字體與圖像

- 中文：系統無襯線字體，優先 `Noto Sans TC`。
- 英文：優先 `Comic Relief`，後備 `Comic Sans MS`、系統圓體。
- 精確站名、時間、錯誤與按鈕文字全部由 HTML 呈現。
- ImageGen 圖片不得承載可讀文字，避免錯字與亂碼。
- 圖片需求詳見 `content/asset-manifest.json`。

### 4.3 iPad 版面

- 直式與橫式都能完成全部操作。
- 主要內容最大寬度 `960px`。
- 觸控區至少 `48×48px`，相鄰控制項至少 `8px`。
- 學生正文至少 `18px`。
- Safari 與 Chrome 不得產生橫向溢出。
- 教師後台在窄螢幕可將左右欄改成清單頁與詳情頁，但資訊順序不變。

## 5. 學生六步流程

所有步驟以 `content/site-content.json` 為唯一內容來源。

| 順序 | 穩定 ID | 操作 | 通過條件 | 證據頁 |
|---:|---|---|---|---:|
| 1 | `step.origin` | 選擇二水 Ershui | 起點為二水 | 1 |
| 2 | `step.destination` | 選擇集集、水里或車埕 | 與起點不同且符合任務；主線為車埕 | 2 |
| 3 | `step.date` | 選擇三個模擬日期之一 | 符合任務指定日期 | 3 |
| 4 | `step.search` | 檢查起點、目的地、日期並查詢 | 三者正確且起訖未顛倒 | 4 |
| 5 | `step.train` | 從 A／B／C 選擇模擬車次 | 主線選 B | 5 |
| 6 | `step.summary` | 勾選 from、to、date、train、depart、arrive | 六欄皆正確且資料一致 | 6 |
| 7 | `step.success` | 閱讀 SAMPLE 車票 | 顯示練習完成且未真實訂票 | 7 |

### 5.1 正確回饋

- 每個 `event.step_passed` 只觸發一次。
- 同時顯示 `You're right!`、綠色勾號、通過邊框及 1 至 1.5 秒動畫。
- 播放短音效；全程提供靜音鍵。
- 第七步播放完成鈴與較完整但不閃爍的慶祝。
- `prefers-reduced-motion` 下改為靜態勾號與淡入。

### 5.2 錯誤與修正

- 錯誤不播放成功音效或慶祝。
- 暖橘文字指出可修正欄位，不使用羞辱性大面積紅色。
- 焦點移到錯誤欄位，`aria-live` 朗讀提示。
- 起訖相同、起訖顛倒、錯誤日期、錯誤車次、交換起訖及返回上一步均寫入事件。
- 教師可以從重播中看見修正歷程。

## 6. Attempt 與事件生命週期

1. 學號格式通過。
2. `POST /api/attempts` 建立 `attempt_id`、短效 attempt token 與開始紀錄。
3. 前端以 `seq=1` 開始追加事件，並保存操作前後的允許狀態。
4. 伺服器拒絕重複或倒序 `seq`、未知事件、未知欄位與任意文字。
5. 每個步驟通過後寫入 `event.step_passed`，再等版面穩定後擷取證據畫面。
6. 第七步先寫入 `event.attempt_completed`，再合成並上傳 PDF。
7. 完成後 attempt 進入 `completed`，既有事件不可由學生新增或改寫。
8. 重做需建立新的 attempt；相同學號同日多次作答不得互相覆蓋。

## 7. 七頁 PDF 證據

- 首頁學號畫面不列入 PDF。
- 每次步驟通過後，只擷取網站主要內容容器。
- 不擷取網址列、其他分頁、通知、裝置畫面或聲音。
- 每頁 A4 橫式，一頁一張過關畫面。
- 頁首包含單元、日期、學號、attempt 末六碼、步驟名稱及頁碼。
- 畫面保留「模擬教材」警語。
- 順序固定為六步加最終成功，共七頁，不可缺頁或重複。
- 七張圖片只在當次操作暫存；完成後於學生端合成 PDF。
- 伺服器驗證 attempt、頁數、大小、檔案類型及 checksum 後寫入 R2。
- R2 成功後將索引寫回 D1，並清除學生端個別暫存圖。
- PDF 不設公開網址，教師下載需每次重新授權。

## 8. 無聲事件動畫重播

本功能不是螢幕錄影，也不建立影片檔。教師端以 D1 中的結構化事件還原相同版本的學生介面，依 `client_elapsed_ms` 播放。

播放器提供：

- 播放／暫停。
- `0.5×`、`1×`、`2×`。
- 時間軸。
- 依步驟跳轉。
- 游標光圈與欄位高亮。
- 事件清單、錯誤提示及 before／after 狀態。
- 全程無學生端音效。

重播必須依 attempt 保存的 `content_version` 使用相容內容，避免日後文案或資料更新造成舊紀錄無法還原。

## 9. D1 與 R2 分工

### 9.1 D1

- `teacher_allowlist`：教師白名單。
- `units`：四單元設定與成果政策。
- `attempts`：一次練習的主紀錄。
- `attempt_events`：操作與修正事件。
- `evidence_manifest`：七頁順序、checksum 與上傳狀態。
- `deletion_log`：刪除稽核，不保存被刪除學習內容。

### 9.2 R2

- PDF key：`evidence/{unit_slug}/{attempt_id}/proof.pdf`
- key 不含學號。
- metadata：attempt ID、`page_count=7`、checksum、建立時間與到期日。
- 不設公開網址。

### 9.3 存取原則

- D1 與 R2 只在伺服器端使用。
- D1 查詢使用參數化 prepared statements。
- 每個 `prepare()` 只包含一個 SQL statement。
- 學生端不可列出、讀取或下載其他 attempt。
- 教師 API 每次都重新檢查 ChatGPT 身分與白名單。

## 10. 教師後台

### 10.1 頂部工具列

- 單元篩選。
- 日期範圍。
- 五位數學號搜尋。
- 同步狀態。
- 登入教師帳號。
- 匯出清單。
- 安全登出。

### 10.2 左欄

- 依日期群組。
- 顯示學號、完成時間、狀態及 attempt 末六碼。
- 同一學號的多筆紀錄各自顯示。

### 10.3 右欄摘要

- 起點、目的地、日期、車次。
- 開始與完成時間。
- 錯誤及修正次數。
- 事件數。
- 七頁證據狀態。

### 10.4 右欄重播

- 無聲動畫、時間軸、速度與步驟跳轉。
- 顯示事件清單與前後狀態。

### 10.5 右欄 PDF

- 七頁縮圖與頁碼。
- 串流預覽及下載。
- 刪除需二次確認，先刪 R2，再清 D1。

## 11. 驗證與授權

- 學生頁公開。
- 教師頁使用平台提供的 ChatGPT 登入，不建立自有密碼系統。
- 伺服器從可信的驗證資訊取得電子郵件。
- ChatGPT 登入只代表身分驗證；能否進入教師後台仍由 `teacher_allowlist` 決定。
- 不接受 `?teacher=1`、隱藏網址或前端密碼作為授權。
- 所有教師 API 在伺服器端再次授權。
- 白名單、刪除與匯出不得由前端自行判定。

## 12. 保存、隱私與安全

### 12.1 保存

- 已完成 attempt：從 `completed_at` 起 365 天。
- 未完成 attempt：從最後事件時間起 365 天。
- 優先使用平台可用的週期性機制清理。
- 若沒有排程，教師後台開啟時進行有限筆數的到期掃描，並提供「立即清理到期資料」。
- 清理順序：刪 R2 → 確認 → 刪 D1 事件、manifest 與 attempt → 寫入 deletion log。

### 12.2 不收集

- 姓名。
- 身分證號。
- 電話。
- 學生電子郵件。
- 信用卡或付款資料。
- 真實訂票代碼。
- IP 位址。
- 真實螢幕影像、麥克風或系統聲音。

### 12.3 輸入與濫用防護

- 學號限制五位數字。
- 事件種類、步驟、欄位及模擬值使用白名單。
- 限制欄位長度、事件批次數、請求頻率及 PDF 大小。
- 拒絕任意 HTML、外部網址及任意檔名。
- attempt token 以短效、不可猜測、伺服器驗證的形式使用；D1 只存 token hash。

## 13. 離線與故障替代

- PWA 快取核心頁面與模擬資料。
- 離線時可練習，事件與七張圖暫存於 IndexedDB。
- 明確顯示：「離線練習，尚未同步」。
- 恢復連線後依 `seq` 冪等補傳，不建立第二個 attempt。
- PDF 與事件都成功後才顯示「教師已收到」。
- iPad 無法使用時，改用同版面 A4 六步紙卡、三張模擬車次卡及 SAMPLE 確認票。
- 教師課前至少以兩台 iPad 測試 QR、音量、旋轉、重新整理、離線及重新連線。

## 14. 無障礙

- 每一步只有一個清楚的 `h1`。
- 所有欄位有可見標籤及正確程式化 label。
- 可用 Tab／Enter 完成，不要求拖曳。
- 有清楚可見的鍵盤焦點。
- 狀態不能只用顏色，需搭配站名、圖示、形狀及文字。
- 正確與錯誤訊息透過 `aria-live` 適度朗讀。
- 動畫不閃爍，尊重 `prefers-reduced-motion`。
- 裝飾圖使用空 alt；有教學意義的圖使用 asset manifest 中的繁體中文 alt。

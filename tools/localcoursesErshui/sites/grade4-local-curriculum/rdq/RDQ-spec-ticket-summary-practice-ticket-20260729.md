# RDQ 需求規格：核對摘要與練習車票改版

## 一句話任務
修正 Firebase 購票練習第5步的核對資訊缺漏，並將第6步改成適合四年級學生的 3D 立體手繪車票。

## 已確認
- 第5步上方路線區必須同時顯示**日期、正式車種與車次、出發時間、抵達時間**。
- 六張核取卡同時顯示欄位名稱及實際值，例如「Train／車次｜區間 2711」，學生看得到資料才能逐項勾選。
- 缺少資料的核取卡不可勾選，並提示學生返回前一步補選；全部六項核對後才能前往第6步。
- 第6步目的地依學生選擇動態顯示**集集／水里／車埕**，不得固定為車埕，時間也要跟隨正式車次。
- 車票最左欄由上至下放 **DATE、TRAIN**；中央為 **FROM 二水**，其下放 **DEPART**；右側為 **TO 所選目的地**，其下放 **ARRIVAL**。
- 刪除 **CAR／SEAT**；**STUDENT**移至車票最右下角。
- 視覺採程式建立的立體票券、陰影及清楚欄位，加上生成式的可愛小火車、綠色隧道與田野裝飾。
- 所有中英文、日期、車次和時間皆使用網頁 HTML 文字，不畫入生成圖片，以避免亂碼並維持響應式排版。
- iPad 保持橫式票券構圖；手機版改為易讀的直式排列，操作目標至少 44px。
- 新增跨步驟自動測試，核對第4步資料與第5步、第6步、PDF及教師後台紀錄一致。
- 教師後台登入頁只顯示一個**密碼輸入欄**與登入按鈕，不再要求教師輸入電子郵件。
- 密碼欄必須使用遮蔽輸入，不顯示明碼，也不提供直接顯示密碼的切換按鈕。
- 教師密碼不得寫入前端程式、Git、規格卡、Firestore、分析事件或錯誤紀錄；部署時存入 **Firebase Secret Manager**，由啟用 App Check 的 Cloud Function 驗證。
- 密碼正確時由後端核發短效教師登入權杖，登入狀態僅保留在目前瀏覽器工作階段；15分鐘內連續錯誤5次即鎖定15分鐘並顯示一般性提示，不回傳可用來猜測密碼的細節。
- 網站頁首將中文名稱**「火車線上購票網站」**與英文名稱**「Buy Train Tickets Online」**放在同一標題列並列顯示，英文不得再縮成中文標題下方的小字。
- 英文標題字級明顯放大並與中文標題共用基線；iPad／桌機以響應式字級維持單行並列，窄手機可等比例縮小但不得截斷、重疊或變回上下排列。
- **全站所有頁面**統一改為適合四年級學生的多巴胺配色，範圍包含課程首頁、四個單元入口與內容頁、購票七步驟、成功頁、教師登入及教師後台。
- 全站色票以亮黃、珊瑚橘、桃紅、寶藍、湖水綠及葡萄紫為主，搭配奶油白內容底與深藍文字；不同頁面可更換主色，但按鈕、成功、警告、錯誤及選取狀態的語意必須一致。
- 多巴胺色彩用於頁首、卡片邊框、按鈕、進度、插圖及重點區塊，不以高飽和色大面積承載長文；正文區保留淺色背景，文字與背景至少符合 WCAG AA 對比。
- 學生操作頁採明亮、活潑及立體層次；教師後台也沿用同一色票，但降低裝飾密度，確保表格、篩選、紀錄及危險操作仍可快速辨識。

## 待確認假設
- 車票保留「教學練習使用｜不可作為真實車票乘車」聲明，並沿用網站現有的兒童可讀字體。
- 不改變第1–4步的日期、目的地與正式車次選擇規則，只修正資訊傳遞、核對互動及票面。
- 目前採用使用者指定的4位教師密碼；因強度偏低，先以 App Check、15分鐘內5次錯誤即鎖定15分鐘、工作階段登入及短效權杖降低風險，日後可直接更換 Firebase Secret 而不修改網站程式。
- 全站多巴胺改版只更換色彩、陰影、邊框與裝飾層級，不改寫四個在地課程單元的既有文字內容與資訊架構。

## 已採納建議
- 實際值完整呈現後才允許勾選；生成插圖不承載文字；iPad與手機各自最佳化；加入資料一致性自動測試。

## 本次不納入
- 真實訂票、付款、座位／車廂選擇、臺鐵會員資料，以及第1–4步以外的功能重構。

## 一段式需求規格
在 **C:\firebase-deploy\在地課程\sites\grade4-local-curriculum** 修改並重新部署 Firebase 網站：全站所有學生與教師頁面套用亮黃、珊瑚橘、桃紅、寶藍、湖水綠、葡萄紫、奶油白與深藍組成的多巴胺設計系統，維持一致語意與 WCAG AA 可讀性；頁首把「火車線上購票網站」與放大後的「Buy Train Tickets Online」置於同一標題列；第5步用路線摘要及六張核取卡完整顯示已選日期、二水、目的地、正式車種車次、出發時間與抵達時間，缺值不可核對；第6步建立 HTML 文字與生成式無字裝飾組成的 3D 立體手繪練習車票，左欄為 DATE／TRAIN，中央 FROM 二水／DEPART，右側 TO 動態目的地／ARRIVAL，STUDENT 位於右下角，取消 CAR／SEAT；教師後台改為只輸入遮蔽密碼，密碼僅由 Firebase Secret Manager 與受 App Check 保護的 Cloud Function 驗證，並加入錯誤次數限制、暫時鎖定及短效教師權杖，確保密碼不出現在前端與紀錄中，同時維持 iPad、手機、PDF及教師後台資料一致。

## 驗收條件
- [ ] 任選一班車後，第5步可看見並核對六個對應實際值，沒有只見核取名稱而看不到資料的情況。
- [ ] 第6步票面欄位、位置及目的地完全符合規格，無 CAR／SEAT，且 3D 手繪裝飾不遮擋文字。
- [ ] 自動測試通過第4→5→6步、PDF及教師後台的日期、車次、出發與抵達資料一致性。
- [ ] 正式 Firebase 網址以 iPad及手機尺寸完成流程，無水平溢位、亂碼或無法勾選問題。
- [ ] 教師登入頁只有遮蔽密碼欄；前端檔案、網路回應、資料庫及日誌均找不到明碼，正確密碼可登入，15分鐘內連錯5次會鎖定15分鐘。
- [ ] 頁首中英文名稱在 iPad、桌機及窄手機均保持同列並排，英文標題清楚放大且沒有截斷、重疊或退回上下排列。
- [ ] 課程首頁、四個單元、購票七步驟、成功頁、教師登入與教師後台皆套用同一多巴胺色票；按鈕及狀態語意一致，正文對比通過 WCAG AA，且沒有因高飽和背景導致文字難讀。

# RDQ 需求規格：四年級在地課程模擬購票網站

## 一句話任務
更新 Word 第4節規劃書，完整定義 ChatGPT Sites 上的四單元入口、模擬購票學生端、共用教師後台，以及 D1／R2 資料架構。

## 已確認
- 學生端首頁為「火車線上購票網站—Buy Train Tickets Online」，輸入五位數學號（例如 **40100**），不輸入姓名。
- 首頁使用四個 ImageGen 原創可愛鐵道場景；配色吸收臺鐵線上購票網站特色，但仍清楚標示為模擬教材。
- 原有六步購票流程不變；七張證據畫面為六個步驟過關畫面加最終成功車票畫面。
- 每一步正確完成即播放「You’re right!」音效與短慶祝動畫。
- 不錄製真實螢幕影片；D1 保存點擊、選擇、修正與過關事件，教師端依時間順序重播為無聲動畫。
- R2 保存七張證據畫面合成的單一 PDF；教師後台可預覽或下載。
- 學生端公開；教師後台必須使用 ChatGPT 登入，伺服器再核對教師電子郵件白名單。
- 學生只輸入學號，不另設活動代碼或班級欄位；每次作答由系統建立唯一紀錄。
- D1 與 R2 資料保存 **1年**。
- 上層首頁為「4年級上學期 在地課程」，提供四個單元入口及右上角統一教師後台。
- 四單元共用資料模型與教師後台；本次只詳細定義「坐火車趣集集」的事件重播及七頁 PDF。
- 本階段更新 Word 規劃，不建立或部署網站。

## 待確認假設
- 同一日期、同一學號可有多次作答，以系統產生的 attempt ID 分開保存。
- 保存期限採完成時間起算365天；到期時同步刪除 D1 紀錄與 R2 PDF。
- 七張畫面只擷取網站內容區，不含瀏覽器網址列、通知或聲音。
- 教師白名單電子郵件於實作階段另行提供，不寫入公開前端程式。

## 已採納建議
- 每筆操作事件包含流水號、伺服器時間與前後狀態，完成後鎖定紀錄。
- 每次作答建立唯一 attempt ID，以區分相同學號的多次練習。
- 完成日起365天同步清除 D1 紀錄與 R2 PDF，並提供教師匯出及手動刪除。
- ImageGen 先製作四張原創場景圖，再以 CSS 製作輕量動畫。
- 「You’re right!」同時使用文字、圖示、音效與動畫，並提供靜音及減少動態效果。

## 本次不納入
- 臺鐵真實訂票、付款、會員、票價及真實個人資料。
- 真實螢幕錄影檔、麥克風、系統聲音或學生影像。
- 其他三個單元的詳細活動紀錄格式與學生操作流程。

## 一段式需求規格
在 **02_第3-10週_坐火車趣集集.docx** 的第4節中，將既有純前端六步規劃改寫為可部署於 ChatGPT Sites 的完整架構：上層網站「4年級上學期 在地課程」提供四單元入口及統一教師後台；學生進入「火車線上購票網站—Buy Train Tickets Online」後輸入五位數學號，依序完成六步模擬購票，每步正確時播放「You’re right!」與短慶祝動畫；D1 保存學生學號、單元、日期、attempt ID、事件序列、步驟狀態與 PDF 索引，R2 保存六步過關畫面加最終成功車票共七頁的 PDF；教師以 ChatGPT 登入並通過伺服器端電子郵件白名單後，可在左欄依日期與學號選擇紀錄，在右欄重播無聲操作動畫、檢視摘要及預覽或下載 PDF；資料保存 **1年**，不連接臺鐵真實訂票、不錄製真實影片，也不蒐集姓名或付款資料。

- [ ] 明確區分模擬教材與臺鐵真實訂票，並保留無障礙、靜音及減少動態效果設定。

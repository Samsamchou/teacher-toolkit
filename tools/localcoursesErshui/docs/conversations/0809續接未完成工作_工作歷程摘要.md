### 4. 重啟後的正式方向

- 先分析四年級上、下學期原有在地課程單元及既定活動。
- 原單元主軸與學習活動不可大幅改變。
- 再分析三、四年級英語部定及彈性課程。
- 將相符的英語單字、句型、生活用語及口說活動嵌入原活動。
- 視單元需要再融入社會或綜合活動領域。
- 每節課必須適合四年級學生實際操作。
- 無法進行實地踏查時，改用官方照片、影片、地圖、教師預錄導覽和教室資料探究。

## 三、確立的教案設計規則

1. 原有在地課程是主體，英語是學習與表達工具。
2. 不因融入英語而把單元改成一般英語課。
3. 每節課先列主要英語口說、核心句型、生活用語、核心英文字詞、延伸字詞與中譯、數位教材、手作教材及學習單。
4. 每節課採 Warm-up、Presentation、Production、Wrap-up 四階段。
5. 每個階段前要有一句能概括活動的主標題。
6. 流程具體寫出教師如何引導、學生如何操作、師生如何互動、分組角色、時間與成果，不能只用一句話帶過。
7. 課綱表格把「學習表現」和「學習內容」分欄，列出完整編號與敘述。
8. 學習目標除保留原課程目標外，還依詳細流程加入英語、資料閱讀、合作、表達與查證目標。
9. 英語句型須真正對應學生部定課程。例如〈扇形車庫〉由 `What is it? It’s a ...` 改為 `What’s this? It’s a ...`／`What’s that? It’s a ...`。
10. 教材製作前先查官方或可信資料，再寫提示詞或生成圖片。
11. 重要事實採「官方主要來源＋另一可信來源」交叉查證。
12. AI 圖片只作教學示意；車站、路線、地標、年代及英文站名仍需人工核對。
13. 圖片中文使用繁體中文；英文偏好 Comic Sans 或兒童易讀字體。
14. 圖片生成前先確認提示詞，不再直接生成未查證教材。

目前學生流程為：輸入五位學號；選最近尚未經過的週五至週日；出發站固定二水並選集集／水里／車埕；選擇搭車時段與車次；核對 `from／to／date／train／depart／arrive`；產生練習車票、分數、PDF及完成慶祝畫面。

其他特點：

## 十二、摘要與練習票的錯誤與修正

### 1. 核對摘要

第5步曾只看到起訖站，沒有清楚看到車次、出發時間與抵達時間，學生無法真正核對。修正後，上方摘要及六張核取卡均顯示實際值；資料缺漏時不能勾選，六項完成後才能下一步。

### 2. 練習車票

原票面不夠吸引學生，FROM／TO 與時間層級不符要求，且有多餘 CAR／SEAT、STUDENT 位置錯誤，目的地也未動態更新。修正後使用 3D 立體手繪與多巴胺配色；左欄為 DATE／TRAIN，中央 FROM 二水下方為 DEPART，右側 TO 所選目的地下方為 ARRIVAL，移除 CAR／SEAT，STUDENT 位於右下角；文字使用 HTML 排版避免生成亂碼，並保留「教學練習使用｜不可作為真實車票乘車」。

## 十三、教師後台功能與修正

### 1. 登入方式

- 只顯示遮蔽密碼欄與登入按鈕。
- 密碼不得寫入前端、Git、Firestore、規格或日誌，由 Firebase Secret Manager 保存。
- Cloud Function 驗證後核發短效教師權杖，使用 custom claim 控制權限。
- 錯誤達限制時暫時鎖定；本摘要不記錄實際密碼。

### 2. 練習日期

後台曾把未來搭車日期當成練習日期。修正後：

- `practiceStartedAt` 為後端可信開始時間。
- `practiceDateTaipei` 為 Asia/Taipei 的實際練習日期。
- `travelDate` 為學生選擇的搭車日期，分開保存。
- 後台與 CSV 依練習日期篩選，並另顯示搭車日期。
- 跨午夜完成仍歸在開始練習日；舊紀錄可依可信 `createdAt` 回填，無可信時間者標示「日期待確認」。

### 3. 作答重播

最初事件動畫只有火車進度條與文字清單，不符合重播學生實際操作畫面的需求。後續確立：

- 支援裝置由學生主動選擇分享目前瀏覽器分頁，使用 `getDisplayMedia({audio:false})` 與 `MediaRecorder` 錄製無聲 720p 低幀率 WebM／MP4，單檔上限 80 MB，受教師權限保護並保存一年。
- 不支援或拒絕錄影時，不阻擋練習，改由事件資料重建七步驟頁面、選項、選取、答錯、核取及換頁；不再只有進度條，原始事件文字清單預設收合。
